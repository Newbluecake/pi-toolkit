## 4. probe:mermaid 报告摘要

101 个用例（R 渲染 ×2 主题、N 网络与 DOM、C 有效配置、F 字体、M 数学、L 限额），Chromium 与 Firefox 结果一致：

- `/probe-sink/*` 命中 **0**（服务端日志 + Playwright `request` 事件双重判定）；`gateBreach` **0**；除 `style-src-*` 外 CSP 违规 **0**（`style-src-*` 噪声：Chromium 4600 条 / Firefox 2426 条，功能无害）；每个 N 用例的 stage MutationObserver 从未见到 img/image/video/audio/source/iframe/object/embed/`use[href^≠#]`；`document.body` 子节点集合渲染前后不变。
- **正向对照**：页面先主动请求 `/probe-sink/control.png`，确认请求日志真能看到命中（探针不盲）。
- **反向验证（探针有牙）**：临时关掉 G1 资源词法检查、DB 审计和 `details` 检查后重跑，出现 62 条失败——`flowimg`/`seqicon`/`details`（bait 节点真的被读到）/classDiagram `fill:url()` 等全部真实发出请求，同时 G5 拦下了其余输出。随后还原源码并重跑通过。
- 图类型实测字符串（22 个）：`block c4 classDiagram er flowchart-elk flowchart-v2 gantt gitGraph journey kanban mindmap packet pie quadrantChart radar requirement sankey sequence stateDiagram timeline treemap xychart`，均在 `MERMAID_ALLOWED_TYPES`（白名单另保留别名 `flowchart`/`class`/`state`）。
- **C 组**：`%%{init}%%` 与 frontmatter 尝试 `htmlLabels:true`、`themeCSS`、`dompurifyConfig`、`securityLevel:loose`、`themeVariables.fontSize:99px`、`flowchart.htmlLabels` 后，生效值仍是站点值（`htmlLabels:false`、`securityLevel:strict`、无 themeCSS、dompurify 白名单不变、`themeVariables.fontSize` 为站点自己的 `16px`）；输出无 foreignObject；§2.2/R2-3/R2-4 的拒绝项得到预期 reason。
- **F 组**：flowchart / sequence / state / class / mindmap 的长中英文标签，每个节点标签落在 shape 内（容差 2 px），sequence 参与者文字落在参与者框内。
- **M 组（数学期望表，实测冻结）**：flowchart ok（按字面文本）、sequence `unsupported`、class ok、state ok、er ok。
- **L 组**：超长文本（>20 000 字符 / >2000 行）⇒ `too-large`，且**未请求任何 `mmd-` 块**；480 边稠密图 ok（Chromium 1363 ms / Firefox 1393 ms）；501 边 ⇒ `too-large`；模拟触屏（`pointer: coarse`）201 边 ⇒ `too-large`；巨大 viewBox ⇒ `svgToImage` 拒绝。

## 5. 偏差与取舍

1. **`ImplResult.rejected` 不能带 `parse`**（接口冻结），R2-3 的布局拒绝改为 impl 抛 `MermaidAuthorConfigError`，`classifyMermaidError` 映射为 `parse`；接口未动。
2. **接口之外的新增导出**（均为追加，不改冻结签名）：runtime 导出常量（`LOAD_TIMEOUT_MS`/`CALLER_DEADLINE_MS`/`EXEC_TIMEOUT_MS`/`MAX_QUEUE` …）和 `MermaidEngineState` 类型；impl 导出两个只读诊断钩子 `pwhProbeEffectiveConfig`/`pwhProbeParseCostMs`（仅 probe 使用，会进入懒加载块）。
3. mindmap 的 `layoutAlgorithm` 允许 `cose-bilkent`（mermaid 自己对 mindmap 的默认值）、`elk`、`dagre`，否则拒绝；`layout` 严格 {elk,dagre}。
4. R2-4「各布局的迭代/尺寸类数值键」：我钉的键名清单见 `MERMAID_LAYOUT_PARAM_KEYS`；另把 `nodeSpacing`/`rankSpacing` 限定在 [0,200]。这是对「尺寸类」的解释，若主会话想更松/更紧只需改常量。
5. G5 前的实体归一化：除数值实体外，`&quot; &apos; &lt; &gt;` 解码为本字符，其余命名实体视为通配符。
6. F 组按计划用「无 CSP 的页面内联渲染同一份 SVG」，实现上用 `page.setContent` 的空白页而不是服务器上的 `/probe-svg/<n>` 路由（行为等价，少一个路由）。
7. **生产构建此刻不含 mermaid**（P2 才接线）。check:web 对此显式处理：`implInGraph:false` 时要求零个 impl 持有者、零个独占 chunk。完整门禁用上表的临时接线验证过，P2 合入后会自然生效。
8. 归属清单相对计划增加字段：`implInGraph`、`containsElk`、包的 `dir`（嵌套版本如 `d3-array@2.12.1` 才能找到各自的 LICENSE）、`embedded`。
9. `THIRD_PARTY_NOTICES.md` 由生成器按 **生产 + csp-probe 两份清单的并集**生成（生产构建接线前只有 probe 含完整 mermaid 闭包）；多出来的条目无害，check:web 只要求「实际输出的包全部被覆盖」。条目标题格式 `## name@version`；条目边界用生成器写入的 `\n---\n\n## `（许可证原文里有 `## ` 小标题，不能当边界）。
10. 首屏集合改为始终沿静态 import 递归后，当前生产构建的首屏 JS 数字没有变化（305,274 B gz，因为该构建没有 modulepreload）；既有测试里断言旧行为的用例已按新语义更新。
11. 「S0 真机」尚未做：需要人手用手机访问。命令：`npm run probe:mermaid -- --lan`（只服务 probe 构建、无认证，会打印警告）。未跑 WebKit（本机缺系统库）。
12. 未跑全量 `npm test`（按要求）。

## 6. 给 P2 的注意事项

- 只 `import type` 或 mock `components/shared/mermaid-runtime.js`；**不要**静态 import `mermaid-impl`/`mermaid`（`vue-tsc` 与归属门禁都会发现：impl 所在 chunk 一旦不独占，check:web 直接失败）。
- 接线后必须先 `npm run build:web` 再 `npm run check:web`（check:web 依赖 `node_modules/.cache/pwh-ui-provenance.json`，陈旧/缺失会失败，CI 与 `prepack` 已是这个顺序）。
- `MermaidOutcome.error.message` 是英文固定短句（≤160，单行，不含原文；parse 错误只带行号）；界面文案请按 `reason` 走 i18n，必要时把 `message` 当次要细节。
- `ok` 结果带 `title`（来自 `<title>`，最多 200 字符）可用作 alt；`width/height` 已是 CSS px。
- 数学公式：sequence 含 `$$…$$` 会得到 `reason:"unsupported"`，message 为 "Diagram contains math formulas (not supported)."（P2 的 `mermaidMath` 文案可据此区分：同为 `unsupported` 时可用 `message.includes("math")` 判断，或我可以在 P2 前把它拆成独立 reason——需你们定）。
- stage CSS 由 runtime 自己 `import`，P2 不要再引入。
- 同版本重新 `build:web` 后旧 daemon 的 64 文件/4 MiB 上限会把新 UI 判为「未构建」，必须 `/webhub restart`（plan §7.5；`static.test.ts` 已覆盖降级占位页）。
- P2 合入后请在其分支上重跑 `npm run probe:mermaid`（plan §12 门禁）。
