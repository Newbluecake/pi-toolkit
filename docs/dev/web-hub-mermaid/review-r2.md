# mermaid 方案复审 r2（gpt-6.1-sol，打回）

## 评审结论：打回

r2 对原意见有实质修订：**10 项在方案层面闭合，4 项仅部分闭合**。归属限域方向已经纠正，但产物覆盖仍有遗漏；G1–G4 尚不能按现文本宣称完整；冻结的生命周期契约仍存在直接矛盾。

本次按末尾三个推荐项评审，不重新争论保留 ELK、不打包 KaTeX、iOS 失败回落源码的已定取舍。“已解决”表示方案口径闭合，不代表尚未实施的代码及验收已经通过。

## 已核查项

- **归属算法**：读取 r2 §7、`/tmp/mmspike/prov-plugin.mjs`、`vite.r3.config.js`、`prov-out.json`。新算法不会再因生成后的共享入口引用而把业务 lazy chunk 扩散为豁免；digest 能绑定已记录文件的最终字节，但当前 public JS 覆盖确实缺失。
- **G1–G4 时序与范围**：读取 Mermaid 的 parse、`Diagram.fromText`、render、配置处理、图片渲染及布局 registry。已知图片字段和 CSS 资源语法可在 draw 前拒绝；没有把尚未发现具体绕过等同于防线已经完整。
- **DOMPurify 兼容性**：核实 `getIconSVG → sanitizeText` 链和 architecture 内置图标调用；读取 r2 spike 及输出报告，确认现有成功判据未检查图元完整性。
- **生命周期**：按 §4 的各计时起点、合并订阅、取消及物理占槽规则推演，发现 R2-1 的明确时间反例；其余主要终态和代次规则已有可实施定义。
- **EPL**：读取 `elkjs/LICENSE.md` 及 bundled 文件版权头；只读命令 `git ls-remote --tags https://github.com/kieler/elkjs.git 'refs/tags/*0.9.3*'` 确认 `0.9.3` tag 存在。保留 ELK 和通过精确上游源码获取地址履行分发义务的方向未发现需要推翻的问题；§8.2 的源码可获取义务引用应写为 **§3.1(a)**，不是 §3.2(a)。
- **Node/安装路径**：读取 CI、package 清单及 pi 的 `package-manager.js:1483–1496`，确认 npm git 安装省略 devDependencies；新增最低版本 web 构建 job 不要求提高本包纯运行时下限。
- **manifest 与部署**：复核统一的 `ui-manifest`/`verifyUiRoot`、public 文件复制及静态缓存路径。128 文件、12 MiB 仍有明确硬边界，未发现此次上调本身引入安全断裂。
- **执行范围**：仅阅读文件和执行只读查询；未修改文件，未运行构建、测试或浏览器探针。
