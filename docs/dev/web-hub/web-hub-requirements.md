# web-hub 需求（澄清稿 v1，2026-09）

## 目标

以 pi-toolkit 插件（settings-gated，`webHub.enabled`）的形式提供一个本地 web 服务，用浏览器**渲染并控制**
多个 pi 进程的 agent 运行结果。

## 已拍板决策（用户确认）

| #   | 决策       | 结论                                                                                                                                                                                                                   |
| --- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | 多进程拓扑 | **独立 daemon hub**：插件按需以 detached 方式拉起一个 hub 守护进程（lockfile + unix socket 去重），所有 pi 进程作为 agent 连入注册；浏览器只访问 hub 的单一 URL；hub 生命周期与任何 pi 会话无关，无连接 N 分钟后自退出 |
| D2  | 进程来源   | **两者都要**：①接管用户已打开的 TUI pi 进程；②网页新建无头 pi（daemon `spawn pi --mode rpc`），该进程加载插件后同样反向注册——两类进程走同一套注册协议                                                                  |
| D3  | 控制粒度   | **完全接管**：实时渲染对话/工具调用/subagent 树/成本；网页发消息、abort、steer subagent；**交互式对话框（ask_user、ctx.ui.select/confirm/input/editor）可在网页作答**                                                  |

## 必须满足的约束（来自项目不变量）

- 零 hang：连接/心跳/租约全部有 deadline；hub 侧对失联 agent 有 reaper；pi 侧 hub 不可达时静默降级，绝不阻塞 agent 主循环。
- `/reload` 同进程重激活：连接不得放模块级状态；`Symbol.for` 守卫 + `session_shutdown` 关连接，不留幽灵节点。
- 子会话 inert：post-guard 注册（subagent 由主进程上报，不单独连 hub）。
- print 模式：所有 socket/定时器 `unref()`，`pi -p` 不能被拖住。
- 进程身份 = `pid + 启动 nonce`；会话是可变属性（`/new`、`/resume`、`/reload` 在 `session_start` 重新上报）。
- 安全：只绑 `127.0.0.1`；token 存 0600 文件；hub 等价于远程 shell。
- 协议握手带版本号，hub 与插件版本不一致时可诊断、可降级。
- 历史回放优先读会话 jsonl（getBranch 语义），实时部分走事件流，hub 不做第二份持久化。

## 待定问题（交架构阶段给出建议）

- Q1 TUI 进程的「完全接管」中，TUI 用户与网页**同时**输入/作答对话框的仲裁（先到先得？锁？）。
- Q2 其它扩展在 TUI 模式下调用的 `ctx.ui.*` / `custom()` 对话框能否被桥接到网页——pi 是否提供拦截点？做不到时的降级口径。
- Q3 前端技术栈与交付方式（随包静态资源 vs 构建产物；jiti 加载无构建步骤的约束）。
- Q4 hub 的实现形态：纯 Node 脚本（随包 `bin/`）还是 `pi` 子命令；升级插件后旧 hub 如何被替换。
- Q5 无头进程的生命周期归属（网页关闭后是否保留、空闲回收策略）。
