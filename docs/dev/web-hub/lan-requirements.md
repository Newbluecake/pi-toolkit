# web-hub 局域网访问 —— 需求（2026-09，用户已拍板）

## 背景

P1 的 hub HTTP 写死只绑 `127.0.0.1`（`src/web-hub/hub/http.ts:46`），Host 头只放行 `127.0.0.1:<port>` / `localhost:<port>`，
鉴权是一次性 token（URL 片段 `#t=`）换 HttpOnly cookie。用户需要从局域网内其它机器用浏览器访问。

## 用户决策

| #   | 决策 | 结论                                                                    |
| --- | ---- | ----------------------------------------------------------------------- |
| L1  | 传输 | **HTTPS**，自签证书（本机有 openssl 3.0.2；运行时依赖仍只能有 typebox） |
| L2  | 认证 | **用户名 + 密码**登录                                                   |
| L3  | 绑定 | **监听所有地址**（0.0.0.0）                                             |

## 约束

- 默认行为不变：不开 LAN 时仍然只绑 loopback、走 HTTP、用 token 登录，P1 的测试与安全性质保持原样。
- LAN 模式是显式开关（例如 `webHub.lan.enabled`，默认 false）。缺少必要条件（没设密码、证书不可用）时**拒绝开启 LAN** 并明确提示原因，回退 loopback，不得静默降级为明文或无密码。
- 密码不得以明文存放在 `pi-subagent.json`；存哈希（scrypt 等 node 内置算法），文件权限 0600，放在 web-hub 状态目录。hub 不读 pi 设置文件（arch §13.3），有效配置仍由拉起者经 env 传入。
- 暴力破解防护：按客户端 IP 限流 + 全局限流；错误信息不区分「用户不存在 / 密码错误」。
- DNS rebinding / CSRF：Host 白名单扩展到本机所有接口 IP、主机名与可配置的额外名字；Origin 校验改为 https 方案；cookie 加 `Secure`。
- 零 hang、零新运行时依赖、`/reload` 无模块级可变状态、print 模式 unref 等项目不变量照旧（AGENTS.md）。
- 前端（src/web-hub/web）要有用户名密码登录表单，仍然禁止 innerHTML。
- `/webhub status|open` 在 LAN 模式下给出 https 局域网地址与证书指纹（便于首次信任），不回显密码或 token。

## 待方案回答

- 证书：生成时机（首次启用 / 接口 IP 变化）、SAN 内容（所有接口 IP + 主机名 + localhost）、有效期与轮换；允许用户自带 cert/key 路径吗。
- 设置密码的交互：`/webhub passwd`（TUI 输入框）还是别的；无 TUI（rpc/print）时怎么办。
- token 登录在 LAN 模式下是否只限 loopback 客户端。
- 同时监听 loopback HTTP + 全地址 HTTPS 两个 listener，还是只起一个 HTTPS listener。
- 会话 cookie 有效期、登出、改密码后已有会话是否失效。
- docker 网桥等非物理接口是否需要单独排除（用户选了全地址监听，靠认证兜底）。

## v5 期间的决策（用户直接 @ 方案作者）

| #    | 问题                           | 结论                                                                                                                                                                                                                                                                                                                    |
| ---- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L23  | HTTPS                          | **先只做 HTTP，不做 HTTPS**；HTTPS 由用户通过其它方式（反向代理/隧道等）自行处理。L1/L9/L12/L14/L15/L18/L20 中与 TLS、本地 CA、nameConstraints、spike、不安全入口相关的部分作废（v4 TLS 设计与 Chromium spike 结论仅存档，见 lan-plan.md §14、lan-spike-results.md）                                                    |

| L23b | 反向代理                       | 不信任 `X-Forwarded-*`，客户端 IP 取 socket 对端；走反向代理时限流按代理 IP 计数，列为已知限制；`trustProxyFrom` 本期不做                                                                                                                                                                                               |
