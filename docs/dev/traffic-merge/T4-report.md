## 3. 偏离与说明

1. **状态变更 API 的 token 只认 `x-record-token` 头**（GET/HEAD 仍接受 `?token=`）。方案原文「x-record-token 头或 ?token=」按字面两者皆可；任务验收明确要求「重放 POST 必须带 token + 自定义头」，故对非 GET/HEAD 收紧为仅头形式——是方案的严格子集（拒绝更多），与 web-hub 的 X-PWH CSRF 先例一致。app.js 恒带头，EventSource/导出链接（GET 语义）不受影响。
2. **缺 Host 的请求**：node HTTP 解析层直接回 400（到不了扩展）。测试断言 `[400, 421]`——关键是永远到不了鉴权/路由。
3. **`/api/sessions` 未走 dbPort**（原因见上表）。T2b 的 ReadQuery 若后续支持字符串主键/自定义排序列，可再迁。
4. **`src/traffic/web/` 只迁了 `app.js`**：方案 §2.1 目标布局的 `web/vendor/*` 未迁——vendor 的字节锁定链（`scripts/traffic/vendor-vue.mjs` → `src/traffic/vendor/VENDOR.json` + `.prettierignore` 条目）不在 T4 文件域，迁了会立刻弄坏校验脚本。page.ts 已把 vendor 解析独立出来（模块同级 `vendor/` → 包根 `src/traffic/vendor/`），后续迁移只需动那一个函数 + 校验脚本两行（建议归 T7 或单独 chore）。
5. **`host` 归 `CreateServerOptions` 闭包持有**（engine 无新字段——engine.ts 是 T2b 并行域）。T3 接 `traffic.web.host` 时把 settings 值传进 `createTrafficServer(engine, { host })` 即可；`index.ts:204` 的 `engine.web ??= createTrafficServer(engine)` 调用点兼容（缺省=127.0.0.1）。
6. **index.ts 的两处过时文案不在本包域**（T2b/T3 正在改该文件，已报告主会话）：`/record status` 的「绑定: 0.0.0.0:PORT (token 鉴权已启用，本机豁免)」——实际已是 127.0.0.1 + /api/* 无本机豁免；`state.ts` 的 `BIND_HOST` 常量及其注释。建议 T3 接 settings 时一并清理（读 `engine.server.address()` 或 server 实例的真实绑定）。
7. **`/api/export` 导出链接**仍带 `?token=`（`<a>` 导航无法带自定义头；GET 接受查询形式）。
