# consult 方案 v3 针对性核验（review-3）

> 范围：只核验 review-2 的 15 条在 v3 正文的落地情况 + 用户最终决定的一致性，不重做全面评审。所有代码引用为本次亲自抽验（文件路径 + 符号名 + 行号）。

## 核验结论：有条件通过

review-2 的 1 阻塞 + 3 严重**全部在正文实质落地，且在代码层面可行**——我逐条对照了 `spawn/waitOutcome` 的返回语义、`runner.ts` finally/迟到两处的时序、pi 的 `options.tools` 双重作用（激活 + registry allowlist）、`usage`/`turns`/`lastTurnStartAt`/`finalText` 的实际写入时点，没有发现推理断裂。**fork 文件残留路径我独立枚举了 7 条，没找到方案未覆盖的新路径**（唯一遗漏项方案自己已声明由 sweep 兜底）。

但有 7 处需要在**包 A 冻结前**定口径或补分支，其中 #1（`StopCause` 类型不兼容）和 #2（`forkExpertSession` 抛错无处置）会直接违反方案自己写下的约定与测试断言，#3（C1 桩把只读边界托付给一条易错的并行列表）是安全边界问题。没有阻塞级问题。
