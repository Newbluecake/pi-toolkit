# web-hub 命令历史 — 真机验收清单（I1）

规格：`plan.md` §8.5（v2）+ §5.3 残留与日志卫生。本清单只覆盖自动化测试够不到的真实浏览器 / 真实终端 / 跨设备行为；集成面（真 hub 子进程 × 真实 stack）见 `tests/integration/web-hub-cmd-history.test.ts`，pi 前提见 `tests/conformance/cmd-history.test.ts`。

## 前置与生效方式

1. 仓库 dev 分支已包含 P0/H1/A1/U1（`e33b984f`…`1e5633fe`）与本包 I1；`webHub.enabled=true`（control 开），`webHub.cmdHistory` 缺省（=true）。
2. **生效三步（顺序任意，按 §8.4）**：
   - agent 侧（recorder、features、`/webhub status` 的 cmd-history 行）：`/reload`（git 安装需重启 pi）；
   - hub 侧（cap `cmd.history.v1`、投影、§4.10 ENOENT 回落）：`/webhub restart`；
   - UI：hub 重启后浏览器**刷新**。
   - 三者都新且会话已持久化（`StatusInfo.features` ∋ `cmd.history.v1`）才进入 historyMode——判定：`/webhub status` 出现 `cmd-history: on · hub-cap on · appended N …`。
3. 环境：本机 pi（TUI）+ 浏览器打开 web hub；另备一台手机/第二设备可访问；tmux 里操作终端，全程可回滚截图取证。
4. 基线取证：`/webhub status` 输出截图（记下 appended/skipped/failed 计数初值）；hub 日志路径 `<home>/.pi/agent/web-hub/hub.log`。

每一步的「取证」都建议：终端截图 + 浏览器截图 + （涉及时）`grep` 结果贴回本文件。

### C. G7：agent_settled 发射窗口内的延迟执行（改动核心动机）

1. 额外以 `-e` 加载一个探针扩展：其 `agent_settled` 处理器 `await` 8 s（见下附探针源码）。
2. 发一条消息，等助手回复结束、探针保持期间（终端无新提示），从**网页**执行 `/record status`。
   - 预期（改前行为是 legacy 卡片拿不到任何输出）：探针结束后卡片出现，cmdId=该次调用，**正文完整**（含 token 链接）；`/webhub status` 的 appended +1。
   - 取证：改前/改后各一截图；会话文件 `grep` 该 cmdId。
3. 再测 2 s 保持（<5 s 认领路径）：同样完整。
4. 占位降级：让探针推迟 >60 s ⇒ 网页先出现「结果暂未记录（可能仍在排队或已中断）」提示；真卡到达后提示消失、卡片出现（二者不同时存在）。
