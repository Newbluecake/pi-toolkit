### 1.2 当前机制与实测信号

依据 memory README、arch §6，以及只读核对 `wire.ts` / `predict/flight.ts`：

- **U/A/E/B/P/S** 仍是自适应召回层；U 是用户轮相关性判断，A 是工具动作的 high-risk 快通道，E 是失败后的召回，B 是上下文压缩后重注，P 是预测，S 是发版状态约束。P/U 可通过 `details.parts` 合并；**本窗口没有 parts 合并事件，S=0**。

## 2. 方法与口径（沿用 11-05 §2）

### 2.1 抽取、上下文和人工判定

- 解析全部会话 memory-inject / memory-predict / memory-recall 记录；头部 `subagent:child` 区分主/子，不根据模型或文件名猜测。
- 对注入回溯 **6 秒邻域内**用户/工具记录，并保留所属用户轮与 `details.trigger`。对异步 E，不能拿最近的成功工具结果替代真正失败来源；精确工具因果不足时，只按能够证明的任务相关性判定，不编造失败原因。
- 判定正文以**会话里实际注入的文本**为准，不用今天已经更新的文件替换历史版本。磁盘块和 `.jev` 用于核对存在时间、权威、后续决定与冲突。
- 四档完全沿用：**useful**=直接相关或后续确实用到；**neutral**=同领域但当前用不上；**irrelevant**=无关；**harmful**=过时/错误且可能误导。没有把「能让 agent 更谨慎」一律算 useful，也没有把「没实际执行错」当作 harmful=0 的理由。
- 对压缩后的 B 样本另读真实 handoff/compaction summary；仅看最后一条短问会把仍活跃任务误判为无关。

### 2.3 召回及与 G2 的区别

- 主会话窗口内 322 个 role=user 记录，排除 13 个 switch_context 横幅/纯附件等非真实请求，得到 **309 个真实用户轮**。按时间等距取 **40 个**，不是只挑「记忆治理」轮。
- 「当时存在」按 `.jev` 首次打标 at、块 created/updated、内嵌日期及实际 transcript 核对。新令第一次说出的那一轮，不反向要求历史记忆已存在；纯状态追问也不强行标上所有同主题用户令。
- topic 用户令按块 authority=user、scope=topic/缺省识别；global 常驻不进入 topic pair 分母。
- **两个分母分别报告**：①与 11-05 对照的漏轮数/抽样用户轮；②与 G2 对照的漏 `(轮, 相关 topic 用户令)` pair/全部相关 pair。
- 线上 segment 去重不是漏召回：同时报告「本轮新 U+P 命中」与「本段此前已经提供」。G2 是每轮独立、空 segment 的重放，所以与真实会话不是同条件实验。两种线上算法的观察值本次都超出 45%，但不能把差值直接解释为生产问句回归。

### 2.4 相对 11-05 的必要差异

窗口约 6.57 天而非约两天；主会话从 1 个变成 5 个，故主层由全量改为固定分层 ≥150；子 P 从全量 35 条改为抽 100/240；E 从抽 13 改为全量 43；G 已消失、增加 R。没有 P on/off 对照、没有付费回放、没有冻结保留集、没有第二评估者。所有比例保留原始分母，不能用数量增长冒充准确率提高。
