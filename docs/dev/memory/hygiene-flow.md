# 记忆系统流程改进（hygiene flow）· 需求方案

> 状态：流程方案已经用户确认（2026-10-29），待出技术方案。技术方案另写 `hygiene-plan.md`，本文件只管流程。

## 需求摘要

- **目标**：记忆从写入到消亡的五个环节都有明确的流程和机制，不再靠 agent 自觉。
- **起因**（2026-10-29 实测）：
  - 专题记忆派单十几次一次都没被召回；
  - 用户 10-21 已解禁的「GPT 临时禁用」旧条在文件里又留了 8 天，10-24 已作废的 droid 派单裁定也一直留着；
  - `append` 是盲写，格式会漂移，而且不刷新 `updated` 时间戳（`str_replace` 会刷），D08 陈旧检查因此会误判；
  - core.md 已用到预算的 94%，没有任何提醒。
- **范围**：本次覆盖原「一期 + 二期」，再加上系统推送。原三期只剩根据实际噪音调优。
- **不做**：自动删除记忆；改动已有的 tidy/restore 事务机制。

## 五个环节

| 环节   | 流程                                                                                                                                                                      | 承载                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| ① 写入 | 先检索同主题条目：有就原地改，没有才新增；写完回显所在小节。**用户令**（命令、拍板、否决）当场写，**经验坑**任务收尾时写。append 刷新 `updated`                           | skill（策略）+ 工具（回显、时间戳）        |
| ② 召回 | **主动注入**（同 quota 模块，不靠模型自己想起来去读），触发机制见下文「主动注入」一节。流程节点规则保留作兜底：派单前、发版前、改 `src/<x>` 前、switch_context 之后必须查 | 注入机制 + skill                           |

| ④ 失效 | 临时规则必须带失效条件（日期或事件）。doctor 报告到期条目；会话开始时提示用户，**用户确认后才删**                                                                         | frontmatter / 条目字段 + doctor + 会话提示 |

## 主动注入：触发机制（2026-10-29 讨论定稿）

**原则**：记忆像 quota 一样主动注入，挂在有意义的事件上，不靠模型自己想起来去读。

### 现状问题（实测）

- 静态块预算 2.3KB，core 占 65%。专题按**文件名字母序**依次填完整索引行，放不下的压成 `also:` 名字列表，没有描述和 when（`src/memory/tiered.ts:716`）。
- 2026-10-29 的实际渲染：13 个文件只有 2 个有完整行（字母靠前），最常用的 pitfalls.md 只剩一个名字。
- 结论：`when` 本质是条件触发，放在静态块里等模型自己匹配是分工错位。

### 分工

- **静态块**：只放每轮必需的内容，即 core 加一份极简目录。
- **条件触发**：全部交给主动注入。主动注入是专题记忆的**主通道**。

### 触发层（四层全要）

| 层              | 信号                                       | 匹配                                                                     | 时机                                                                                     |
| --------------- | ------------------------------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| T1 动作触发     | 工具名 + 参数模式、文件路径                | 确定性规则                                                               | 默认附在工具结果里（事后）；标了 **gate** 的高危条目（发版、push、删除类）在动作前拦一次 |
| T2a 输入·关键词 | 用户消息                                   | 关键词命中直接注入                                                       | 输入时                                                                                   |
| T2b 输入·判断器 | 用户消息（只看用户本人发的，不看系统注入） | 关键词没命中时由判断器兜底；尽量与 topic-switch 的相关度判断共用一次调用 | 输入时                                                                                   |
| T3 边界触发     | 会话开始、switch_context、压缩之后         | 重新注入上一段相关过的条目                                               | 边界事件后                                                                               |

不采用按轮数或定时的触发（今天 `[todo]` 提醒的噪音就是这么来的）。

### 配套规则

- **冷却去重**：同一条在同一段上下文里只注入一次；switch_context 或压缩之后重置。先例是 quota 的阶梯冷却（`2257c369`）。
- **粒度**：注入相关的那一条或那一节，不注入整个文件。
- **触发规则谁来写**：agent 写入记忆时顺手写触发规则，并在回复里回显给用户，用户不同意可以要求修改。`when` 从给模型看的自然语言变成给系统执行的规则。

## 待技术方案回答

- 条目级失效条件的表达方式：放在条目行内标记，还是放在 frontmatter？必须兼容现有 golden（`memory-legacy-golden.json`、`memory/{tiered,doctor}-golden`，属 B 级契约 golden）。
- 用户令和经验坑怎么区分标记（现在只有文件级的 `source: agent`）。
- 推送的匹配源（`read_when`、关键词、流程事件）、噪音控制（频率上限、去重），以及在 sysprompt-stable 冻结快照与 tail 更新机制下注入在哪里（I9：功能关闭时输出必须逐字节不变）。
- 「会话开始时提示」放在哪个位置，并确认子会话保持惰性（I6）。
