# 记忆系统流程改进（hygiene flow）· 需求方案

> 状态：流程方案已经用户确认（2026-10-29），待出技术方案。技术方案另写 `hygiene-plan.md`，本文件只管流程。

## 需求摘要

- **目标**：记忆从写入到消亡的五个环节都有明确的流程和机制，不再靠 agent 自觉。
- **起因**（2026-10-29 实测）：
  - 专题记忆派单十几次一次都没被召回；
  - 用户 10-21 已解禁的「GPT 临时禁用」旧条在文件里又留了 8 天，10-24 已作废的 droid 派单裁定也一直留着；
  - `append` 是盲写，格式会漂移，而且不刷新 `updated` 时间戳（`str_replace` 会刷），D08 陈旧检查因此会误判；
  - core.md 已用到预算的 94%，没有任何提醒。
- **范围**：本次覆盖原「一期 + 二期」，再加上系统推送。原三期只剩根据实际噪音调优。
- **不做**：自动删除记忆；改动已有的 tidy/restore 事务机制。

## 五个环节

| 环节   | 流程                                                                                                                                                                  | 承载                                       |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| ① 写入 | 先检索同主题条目：有就原地改，没有才新增；写完回显所在小节。**用户令**（命令、拍板、否决）当场写，**经验坑**任务收尾时写。append 刷新 `updated`                       | skill（策略）+ 工具（回显、时间戳）        |
| ② 召回 | **系统推送**：用户消息或流程节点命中专题的触发条件时，自动附上「相关记忆：X」。**流程节点**规则保留作兜底：派单前、发版前、改 `src/<x>` 前、switch_context 之后必须查 | 注入机制 + skill                           |
| ③ 覆盖 | 新令落盘时必须检索冲突的旧条并处置（替换或标作废），不能只追加。用户令类冲突要在回复里点明「已作废旧规则 X」                                                          | skill                                      |
| ④ 失效 | 临时规则必须带失效条件（日期或事件）。doctor 报告到期条目；会话开始时提示用户，**用户确认后才删**                                                                     | frontmatter / 条目字段 + doctor + 会话提示 |
| ⑤ 整理 | doctor 发现预算超过 80% 或有到期条目时，提示用户跑 `/mem tidy`。先看 dry-run，由用户确认                                                                              | doctor + 提示                              |

## 已拍板（2026-10-29）

| #   | 问题     | 结论                                                                                            |
| --- | -------- | ----------------------------------------------------------------------------------------------- |
| Q1  | 到期处理 | 提示用户，确认后再删（不自动删、不静默隐藏）                                                    |
| Q2  | 召回触发 | 系统推送（流程节点规则保留作兜底）                                                              |
| Q3  | 范围     | 流程 + 小机制 + 推送，一次做完；三期只剩调优                                                    |
| Q4  | 权限     | 用户令类条目只有用户能作废，agent 只能提议；经验类条目 agent 可自行修改（依据 `source: agent`） |

## 待技术方案回答

- 条目级失效条件的表达方式：放在条目行内标记，还是放在 frontmatter？必须兼容现有 golden（`memory-legacy-golden.json`、`memory/{tiered,doctor}-golden`，属 B 级契约 golden）。
- 用户令和经验坑怎么区分标记（现在只有文件级的 `source: agent`）。
- 推送的匹配源（`read_when`、关键词、流程事件）、噪音控制（频率上限、去重），以及在 sysprompt-stable 冻结快照与 tail 更新机制下注入在哪里（I9：功能关闭时输出必须逐字节不变）。
- 「会话开始时提示」放在哪个位置，并确认子会话保持惰性（I6）。
