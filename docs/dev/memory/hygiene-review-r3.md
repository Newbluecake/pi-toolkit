## 对 O16、O17 推荐的意见

- **O16：同意推荐 (a)**。理由成立：「拦一次」防不住明知故犯；条件客观判定 + 查不到即不成立（fail-open）+ 条件消失即放行，不会成为系统级死锁。两点补强：① hold 拦截期间**只拦不重复注入正文**（沿用段内去重），否则每次重试多一条最多 4KB 的消息；② hold 的 reason 文案要与普通 gate 区分，明示「条件仍成立，本次及后续重试都会被拦，直到 <条件> 消失；确需继续请先问用户」——否则模型可能陷入「重试-被拦」循环烧 token。真正的逃生路径是用户（改规则或终止卡住的任务），§9 应写明。
- **O17：同意推荐 (a)**。工具失败频率远高于用户消息（测试红、命令敲错是常态），对话模型每次约 2s 且按次计费，错误循环里成本与噪音都会被放大；Q13 原文就是「由分类器挑」。注意与必修项的衔接：A「无分类器」的判定应改为「**整个分类器列表**都不可用」，而非单个分类器熔断。
