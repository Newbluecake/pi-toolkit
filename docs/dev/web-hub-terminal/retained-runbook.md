# Fixed O7239 → retained unknown: local maintenance runbook

**Development/independent acceptance only. Not authorization to operate a site, install, stop a user's
processes, reboot or deploy.** Obtain separate maintenance authorization first. This is a trusted
same-uid operator protocol, not protection against malicious same-uid code/root running old binaries
or editing the evidence. There is no daemon, live bridge, Inspector or historical-cgroup prerequisite.

## Contract

Stop resource/control publishers and writers, not necessarily every old shell/descendant. Capture all
fixed O terminal sources, retain one unknown obligation per original resource, and publish N only with
honest remaining quota. Never attach/adopt/close/release those cold resources. PID absence, manual shell
exit, TTL, login, new agent/session/epoch, reload and CLI retry do **not** reduce debt. Every requesting
principal pays **all** legacy obligations. Proven sessions pay their own rows; unknown session attribution
charges every session. Normal new reservations/prunes preserve the independent legacy array.

Original `fresh` and strict real-ACK `v1-clean-checkpoint` empty initialization are separate, unchanged
operations. Even zero retained obligations use `offline-retained-unknown`, never guess fresh/clean ACK.
Old O does not understand this ledger, so rollback is **ordinary O with terminal OFF only**, never O on.
Future known-different real kernel retirement needs exact evidence + actual CAS + durable completion;
unknown boot stays charged. This work does not perform or prove a reboot/physical legacy cleanup.

## Build/distribution

Git developers: run `npm run build:maintenance` using the already available pinned dev toolchain.
That generates self-contained `dist/maintenance/cli.mjs`, manifest, notices and this runbook. Source
`tsx`/cycle demonstrations are not a distributed maintenance executable. `npm run build`/prepack and
release packaging include the same directory. npm bin is `pi-terminal-maint`. An unpacked consumer

No implicit dependency or browser installation/fallback. The original strict private `fresh|cycle`
source tools remain separate; their constructed scope is not existing-site history evidence.

## Phases (only after separate actual maintenance authorization)

1. Save work; disable the real auto-start/update paths. Normally stop all old pi/agent/hub/control
   publishers/writers. Known helper/shell residue may remain charged; never broadly kill processes.
2. Run `pi-terminal-maint retained-preflight --installation I --state S`. Review exact refusal facts;
   never force, delete witnesses/sockets/partials, edit a journal to empty or supply fake drain JSON.
3. `pi-terminal-maint retained-initialize --installation I --state S --evidence E` seals the configured
   entries, pins/backs up terminal sources, persists source/installation/operation/mapping links and
   writes marker/witness/A-empty+exact-L ledger, then `initialization-complete`. Record operation O.
   Initialization alone does NOT publish a package. Unknown/inconsistent partials remain and refuse.
4. `pi-terminal-maint publish-new --installation I --expect-operation O` separately prepares the
   immutable terminal-generation floor/publication, CAS-updates only package/terminal configuration,
   actually loads/activates the selected package through the installed SDK, then normally exits the
   load-only probe. It binds NO agent session (therefore no auto-start/terminal declaration if the
   parent CLI dies), makes no model request and constructs no ModelRuntime/auth loader itself. It rechecks original
   source/current ownership before durably completing publication. This is identity, not PTY proof.
   The fixed launcher uses source-forced, filesystem-cache-disabled loading of the measured release;
   source/CLI/pi runtime/floor/config checks and actual fork share the installation lock.
5. Independent `pi-terminal-maint resume --installation I --state S --operation O` reopens durable
   records under NEW real locks/singleton. It never resets subsequent A or reimports legitimately
   retired L. It completes a consistent pending publication or returns the same completed result.
   A preparation/temp/partial is not completion and inconsistent/ambiguous states are not healed.
6. `pi-terminal-maint rollback-inspect --installation I --state S` always refuses retained O terminal-on.
   After normally stopping N controllers/writers, `publish-old-off --installation I --expect-operation O`
   retains v1/v2/L/evidence and the N terminal-generation floor, sets real O terminal-off binding and
   verifies actual old package loading. It does not restore authentication files. To return to N,
   explicitly `publish-new` again; the SAME L and quota remain.

Only a durably identified **tool-created maintenance socket**, with exact original state/profile/
namespace/socket metadata and the actual former maintenance process no longer present, may be
recovered after CLI death. This never unlinks an original O/N hub socket/witness or releases resources.
Unknown sockets/start locks, missing owner record, changed inode/metadata, alive owner or unsupported
boot/namespace refuse. The kernel flock has no stale-PID reset. No delete/GC/force/reset/adopt-hot path.

## Backup/durability boundaries

Only `S/terminal-v1/**`, `.terminal-initialized-v1`, optional independently consistent flat
`terminal-resource-fence-v1.json`, and `.terminal-authority-archive-v1/**` are captured. Includes empty
directories and owned safe opaque regular files; records original dev/ino/uid/gid/mode/size/time/hash
and membership. Exclusive0600 backup temp -> fsync -> rename -> parent fsync -> final pins. Caps:
512 files/16MiB, depth8,128 directories,512 members/directory; authoritative JSON ≤2MiB, witnesses smaller.
Symlinks/hardlinks/special files and ambiguous authoritative locations/partials refuse the terminal
migration, not ordinary WebHub/auth startup. Original source bytes/path identities remain unchanged.

Auth DB/WAL/SHM, token, TOTP key, rotate intent and auth/session state are **not backup or restore
inputs**. SDK/ordinary-service validation uses its own normal original runtime protocol, never auth
replay/rollback. A failed terminal import does not make auth success depend on terminal cleanup.
Normal O-off ordinary auth/public SSE and return-to-N are separate real integration gates.

## Evidence limits

Actual private ordinary unpatched O0/O1/O2(two SDK sessions), later independent CLI, N native PTY,
service/SDK restart, cold refusal/remainder/E_LIMIT, standalone publication CLI self-exit/resume,
O-off SDK/service and provided Chromium are separately recorded by their tests/reports. Component
IO/fault/old-boot tests identify simulated facts. Hardware GPU, Firefox/devices/OS IME, real mounts,
real kernel reboot/powercut/real full device remain NOT RUN. Passing these gates is not site deployment
approval; P7 migration/accounting/UI acceptance must remain independent.
