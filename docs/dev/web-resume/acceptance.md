# web-resume（web 恢复会话 + sub 会话彻底隐藏）· 真机验收清单

对应施工方案：`docs/dev/web-resume/plan.md`（v2 + r1/r2 处置，§9 用户裁定）。每条给出**操作 → 预期 → 取证方式**。
通用前置：

- 本机 `pi`（装了 pi-toolkit，`webHub.enabled`；浏览器访问走 `/webhub open`）+ 一部手机（R5/R6 需要 LAN）。
- 准备一个有历史会话的仓库目录（≥3 个 48h 内会话 + ≥2 个 48h 外会话 + 至少 1 次 subagent 派发留下的子会话文件）。
- 子会话文件位置核对：`ls ~/.pi/agent/sessions/--<编码后的仓库路径>--/`，凡第 2 行是
  `{"type":"custom","customType":"subagent:child",…}` 的文件就是子会话（v0.4.0 起）。
- 已知固定残差（与 plan §2.1/§2.5/§7 一致，验收时不判故障）：
  - **盲区 A**：v0.4.0 之前创建、且父会话文件已删除的子会话无法识别（无自标记、无 `subagent:run` 记录可查）。
  - **盲区 B**：超大会话目录（成千上万个文件）在最初几次打开列表时 provenance 回填未完成，旧子会话可能短暂可见；
    反复打开几次后收敛消失。
  - **W1**：切换执行点复验与 pi `SessionManager.open` 之间隔着异步 `session_before_switch` 钩子，期间的文件替换只能事后
    检出（`resume:mismatch`，effect unknown）；「换走又被换回」完全不可检测。
  - **W2 / D5-a**：pi 不锁会话文件；一个正被**未接入 web 的终端**空闲打开的会话无法发现（size/mtime 只是活动信号，非占用证明）。
- **已修复的产品缺陷（2026-10-16，P4 conformance C2 发现，当天修复）**：真实会话切换后旧 extension ctx 失效，
  `refreshStatusLine` 读 `ctx.ui` 抛错曾导致 `__pick` 的 `cmd_late` 永不上报。修复见 `src/web-hub/agent/index.ts`
  （`readStatusTheme` 不抛、`onChanged`/hold `publish` 逐步隔离），C2 与 `wiring-resume.test.ts` 均已钉住。
  真机验收时若 R3/R6 出现「切换成功但 ctl 项停在进行中 / 10s 后提示未确认」即为回归，按缺陷上报。

## R1 TUI `/resume` 过滤（sub 会话彻底隐藏，D1）

| 项   | 内容                                                                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 在准备好的仓库里起 `pi`，先派发一次 subagent（产生新子会话），然后输入 `resume` 回车（= `/resume-recent`，48h 窗口）；再 `/resume-recent --all`。                                                         |
| 预期 | 两个列表里都**看不到任何子会话**（既无行、也无 `--sub` 参数、无「含 subagent」开关、无「已隐藏 N 个」计数行）；父会话正常出现；列表标题正常（skill 信封剥除、无 `[sub:type]` 前缀——该改标题路径已删除）。 |
| 取证 | 对照第 2 行含 `subagent:child` 的文件名与列表行；子会话基名（`…_<id>.jsonl`）不出现在任何列表项；48h 外的父会话只在 `--all` 出现。                                                                        |

## R2 web 入口与列表（D3/D7）

| 项   | 内容                                                                                                                                                                                                                                                                                                                   |

| 取证 | 弹窗打开时 `~/.pi/agent/web-hub/logs/hub.log` 无新增行（零 hub 改动，全部走既有 `cmd` 通道）；列表条数与 R1 的 TUI 列表同目录一致（sub 剔除后）；翻到底出现 partial/truncated 提示（大目录时）。                                                                                                                       |

## R3 web 切换（同一 pi 进程内换会话）

| 项   | 内容                                                                                                                                                                                                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 操作 | 在列表里点选一个目标行 → 等待页面跟随。再切回原会话（原会话行现在带「当前」徽标，点另一个方向切回）。                                                                                                                                                                          |
| 预期 | 点选后页面状态依次 `picking → switching` → 会话 id 变为目标（对话框关闭，转录跟随新会话）；「恢复」过程**不新起进程**（agentKey 不变）；再切回原会话同样成功。切换完成后 ctl 项应立即收尾（`cmd_late` ok）；若停在 switching 并 10s 后提示「未确认切换」即为开头所述缺陷回归。 |
| 取证 | hub 页面头部会话 id/转录确实变为目标；`fleet`/进程列表无新 agent；原会话文件未被追加（`ls -l` mtime 不变），目标会话文件的 mtime 仅在下次对话时前进。                                                                                                                          |

## R4 忙时可看不可切（D4）+ 活动会话二次确认（D5-a）

| 项   | 内容                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | ① 让 agent 正在长回复（流式中）时打开列表并点选一行；② 列表里选一个**另一个 web 窗口正开着**的会话（或一个 30s 内刚被写过 / 列出后又被改动的文件）点选；③ 底部披露行。                                                                                                                                                                                                                                     |
| 预期 | ① 弹窗顶部横幅「Agent 正在回复，结束后再切换」，行禁用（浏览不受阻）；② 第一次点选返回 `E_CONFIRM_REQUIRED resume:active-elsewhere`，行内出现二次确认块，**再次确认**后才真切换（带 `confirm` 的新请求、新 cmdId）；行上如已知另一 live 卡片占用则直接显示「已在其他窗口打开」徽标，也需本地二次点击。③ 列表底部常驻披露：「pi 不锁会话文件；若该会话正在一个未接入 web 的终端里空闲打开，这里无法发现。」 |
| 取证 | ① 流式期间列表可开、可搜索；② hub 日志 / 浏览器网络面板可见两次 `cmd`（第二次带 confirm）；未确认前目标会话文件 mtime 不变。                                                                                                                                                                                                                                                                               |
