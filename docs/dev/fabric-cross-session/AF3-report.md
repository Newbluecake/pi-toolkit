## 给后续包的接口（AFW/AF4/AF7 必读）

`XsAgentPort`（`agent/xs.ts`，由 `fabric/xs/activate.ts` 的 `webHubDeps()` 装配，AFW 域）新增两个可选 hook，**缺省 ⇒ auto 引擎完全惰性、不发帧、不记录**：

```ts
aliasAuto?(): {
  enabled: boolean;                 // fabric.crossSession.alias.autoFromCwd（activate 冻结）
  cwd: string | undefined;          // 当前会话 cwd（deriveAutoAlias 的输入）
  home: string | undefined;         // os.homedir()
  tmpdir: string | undefined;       // os.tmpdir()
  decided(sessionId): boolean;      // I8「人工已决定」标记（AF4 写、AFW 读；读异常被桥按 true 兜底 = 不 auto）
  handoffPending(): boolean;        // AF7 的 /new 交接槽；AF7 落地前恒 false
} | undefined;
notifyAliasAuto?(text: string): void;  // AFW 按 notifyAliasLost 的方式接 ctx.ui.notify
```

- **AF4**：`/fabric status` 的 `auto skip:<token>` 后缀读 `xsBridge.aliasAutoSkip()`（`undefined` ⇒ 不加后缀）；`held (auto)` 读 `aliasCache().current()?.origin`。人工写路径的 `markDecided` 先写后发由 AF4+AFW 实现，桥只消费 `decided()`。`--force` 本地拒绝（旧 hub）可判 `E_XS_OFF` ∧ `reason:"hub-v2"`。
- **AF7**：`bridge.handoff(alias, prevSessionId)` 已实现（v2 门控含在内）；reconcile 的 ①（pendingHandoff 优先于 auto）尚未接——当前 `shouldAutoClaim` 的 `pendingHandoff` 事实已经由 `handoffPending()` 供给，AF7 只需在 `fabric/xs/activate.ts` 提供真值并在 reconcile 尾部加 handoff 分支（或按方案直接落在 `agent/xs.ts`，AF7 文件域允许）。
- 触发点无需新增：attach 与每次 hello_ack 走 `onHubCapsAlias()`，`/fabric join` 后的 `refreshAlias`（commands 层）也调 `cache.reconcile()`，auto 尾巴都在 reconcile 里；join 的 membership epoch 递增自动给出新的去重键。

## 与方案的偏差

1. **`XsAliasCacheEntry.origin?: "auto"`** 落在 AF0 的文件 `types-alias.ts`（AF0 报告已声明类型是提案、可由实现包调整）。不加这个字段，AF4 无法渲染 `held (auto)`。仅类型 + 桥内镜像，无 wire 变化。
2. **`aliasOp` 新增第三参 `appliedSink`**：方案要求「本次 get 已应用 ∧ none」才 auto；原实现应用后不向调用方暴露「是否已应用」，事后重判无法区分「stale 丢弃」与「applied none」。sink 只在确实 apply 时被写入，语义精确。
3. **重试前复核门控与缓存**（方案只写「等 1–5s 重试一次」）：窗口内可能发生 join/leave（epoch 变）、人工 set（I8 人工优先）或 detach；重试在触发时复核去重键、sid、`aliasUsable`、v2 cap、`decided`/`handoffPending` 与「缓存仍无别名」，任一不满足即放弃。不改变「每个键至多一次尝试 + 一次重试」的上界。
4. **hub 错误码的 `{detail}` 花括号后缀在桥内解析**（`E_XS_ALIAS_BUSY{queue}` → base+detail，与 commands 层 `aliasErrorText` 同一形状）。方案行文把 BUSY 的细节当字段，线上实际编码在 code 后缀里。
5. `decided`/`handoffPending` 读取异常一律按 true 兜底（fail closed：宁可不 auto，不冒与人工决定竞争的风险）；`aliasAuto()` 整体抛错视为 hook 缺失（引擎惰性）。
6. `shouldAutoClaim` 的 `mainSession` 事实在桥内恒传 `true`：桥只在主会话构造（I6），子会话无 xs 接线，天然不 auto——方案的「子会话不构造 auto」单测由「无 `aliasAuto` hook ⇒ 惰性」与既有 off-golden 覆盖。
