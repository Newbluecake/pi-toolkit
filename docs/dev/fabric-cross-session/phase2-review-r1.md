# fabric 二期方案评审 r1（gpt-6.1-sol，打回）

## 评审结论：打回

评审对象：`240aacd4` 中的 r1.1；P1–P10 按推荐方案评审，不扩大到子 agent 跨会话。

主会话专用工具、独立中继、不自动重试的方向可行；但**首次唤醒能力判定、启动超时后的监管、会话身份与成员资格绑定**尚未闭合，不能据此冻结 XS0 契约并开工。

## 已核查项

- **版本与只读边界**：执行 `git show --stat 240aacd4`、`git diff 240aacd4 -- docs/dev/fabric-cross-session/phase2-plan.md`、`git status --short`。评审期间后续提交仅给该方案追加了拍板结果；上述问题依据 `240aacd4` 正文。未修改文件，未运行会产生构建、缓存或测试产物的命令。
- **背景与第一期约束**：阅读 `plan.md` §6–§12、W2–W6 报告及 G-report，核对接受证据、quiet 通知、unknown 不重试、golden 和第二期存档边界。
- **主会话工具现状**：检查 `src/service/runtime-adapter.ts` 正常注入及 consult shadow 分支、`src/index.ts` 注册点。A1 的“主会话没有 message_agent”成立；新增主会话专用工具可避免直接修改该 schema。
- **路由与授权**：检查 `src/core/message.ts` 的 `NodeRef`、key 校验、`authorize()`，以及 `src/fabric/router.ts` 的 `admit()`。A2 对树内身份、running 检查及 unrelated 拒绝的描述成立；独立 xs 通道有实际依据。
- **pi 边界及零 hang 假设**：检查 `src/adapters/pi-compat.ts`，并直接读取安装的 pi `dist/core/agent-session.js`、`agent-session-runtime.js`、`extensions/{loader,runner}.js`，核实 custom 事件、预启动压缩、sendMessage void 包装、abort、异步事件处理及切换顺序。
- **栅栏现状**：检查 `src/web-hub/agent/compaction-state.ts` 的 D13/D26、`resume-exec.ts` 的 exec claim/switchInFlight、`src/topic-switch/wire.ts` 的 hold/B1，以及 `src/goal/hook.ts`。差异表否定 `!isIdle() && signal===undefined` 启发式是正确的，但事件窗口的超时与释放仍有上述缺陷。
- **hub 请求模式与协议兼容**：检查 `agent-server.ts` 的 fsb_req 前置分派、`registry.ts` 的显式 reply 关联、`connection.ts` 的请求截止及 cap 门控。检查 `protocol/version.ts`：PROTO 为 1.2、兼容比较只看 major；`fsb.v1`、LAN 2FA 已有新增可选帧不升 PROTO 的先例，P9 推荐可成立，前提是所有发送路径严格 cap-gated。
- **身份与成员生命周期**：检查 `Connection.attach/detach/setSlot`、`Registry.onFrame(session/status/session_detached)`。实际存在跨会话复用连接、session/status 分离及保留旧状态的行为，因此不能只凭 socket 与 joined 布尔值建立会话授权。
- **安全与 provider 投影**：检查 `command-policy.ts` 的 override 优先级、`command-capture.ts` 的 `isWebInvocation`、`commands/webhub.ts` 的执行点硬门禁；检查现有 `formatWakeResult/formatInbox` 的 JSON 元数据、nonce 及边界中和。pi `messages.js::convertToLlm()` 当前确实只将 custom 的 content 投影为 user 消息，不携带 details；nonce 和“不可信输入”说明只是卫生措施，不构成模型权限隔离。
- **缓存与第一期回归面**：检查 `tool-scope.ts`、consult `shadow-tools.ts`、sysprompt `hub.ts`、两类相关 conformance 测试及 wake-off golden 测试。工具按 activate 冻结、成员 live 状态不改变 schema 的方向正确；主会话开启功能会有一次预期工具前缀变化，不能把“新旧功能前缀相同”作为 C-X5 断言。
- **状态机**：检查 `state-machine.ts::INPUT_KINDS` 与 `tests/core/core.test.ts`：当前确为 17 类输入、204 格矩阵，并从同一输入表生成性质测试。按推荐的主会话专用 Controller 设计，无需给子 run reducer 新增输入；但新 Controller 自身仍须覆盖上述异常转移。
