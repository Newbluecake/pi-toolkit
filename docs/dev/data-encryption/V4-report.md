## 2. 流程各步与状态文件对照（§1.4 ↔ §1.6）

状态文件：`~/.local/share/pi-toolkit-secure/.txn/convert-<名字>.json`，0600。`.txn/` 必须是本用户的 0700 目录且不是符号链接。每次写入都按「tmp（O_EXCL / O_NOFOLLOW，0600）→ fsync → rename → fsync `.txn/`」的顺序（`writeState`）。同目录还有：`.modes`（第 4 步，冻结前记录的原 mode）、`.base`（第 6 步权威检查的清单 = 基线）、`.hashes`（第 7 步的拷贝哈希）。这三个文件都由 tree worker 以独占方式创建，并且已 fsync。

`--abort` / `--resume` 在动任何东西之前先做三件事（r3.1）：`authorizeState`（状态文件里的路径必须等于推导路径与登记项，见 §8 B1）→ `reapLeftoverWorker`（证明状态里记录的 worker 进程组已不存在，B4）→ `--resume` 另做 `verifyVaultForResume`（M5）。R-B / R-A（`recoverConvert`）每一步都依据**实际状态**：

1. **R-B 1，删除原路径上的链接**：要求它是符号链接、目标等于 `<work>`，并且 inode 等于记录的 `link`。如果没有记录 `link` 但有 `linking:true`，则要求属主是本人。删除时先用 NOREPLACE 改名到 `.pi-secure-unlink-<txid>`，复核身份后才 unlink；换入的对象会被改回原处，不会被删。
2. **R-B 2，恢复权限**：先整份校验 `.modes`（rootId 等于本次源目录；每条 rel 相对、无 `..`/`.`/空组件、无 NUL、规范化后不变、≤4096 字节、≤256 层；mode ≤ 07777），任一不合法 ⇒ 整个恢复拒绝（B2，fail closed）；合法时才对源目录树现在所在处（备份路径或原路径，按 inode 判定）恢复，可重复执行。任何条目未能恢复，或冻结后 `.modes` 缺失 ⇒ 剩余项「回滚不完整」（M9），状态文件与 `.modes` 保留。
3. **R-B 3，改回原名**：只有原路径不存在时才用 NOREPLACE 改回；原路径被占用时保留备份并报告。
4. **R-A，新库改名保留（r3.1 B3，不再删除）**：只在源目录已回到原路径、并且本 txid 确实建过布局时执行。依次要求：卸载后 mountinfo 显示 absent、租约空闲、卸载**后**重新 lstat 得到的 dev+ino 与记录一致、新库内无占用；满足后先挂载点、再 `<dir>`，各用 `RENAME_NOREPLACE` 改名为同级 `<基名>.aborted-<txid>`（已存在则不覆盖、保留并报告），输出路径与「内含本次拷贝的密文，核对后可自行删除」；只有本 txid 创建且已为空的挂载点目录经身份核对后 `rmdir`。布局在记录 ids 之前就中断时，只有纯 createLayout 骨架才被改名。最后撤销登记项（仅当 pending 仍是本 txid；V0 的 `missing` 视为幂等成功）。
5. 全部完成才删除状态文件；否则状态文件保留，列出剩余项，exit 74。

## 3. 各中断点的 `--resume` / `--abort` 行为

前提：`--abort` 要求登记项**不存在**，或仍带 `pending === "convert:<txid>"`。登记项已提交（pending 已清且 origin 一致）⇒ 76「转换已完成，不能撤销；备份仍在 …」；pending 属于其他 txid ⇒ 76。`--resume` 要求 pending 等于本 txid，或者已提交且 origin 一致（只做收尾）。没有状态文件 ⇒ 66。两者都持有转换锁，都不需要口令。

| 中断点（kill -9 / 断电时的状态）                                                           | 磁盘上的实际状态                                        | `--resume`                                                                                                         | `--abort`                                                                                         |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 第 1 步之后、`registerVault` 之前                                                          | 只有状态文件                                            | 76（phase < synced）                                                                                               | 登记项不存在、未建过布局 ⇒ 什么都不碰，删除状态文件，exit 1                                       |
| 第 2 步（已认领、布局可能建了一半、可能已挂载）                                            | 登记项带 pending；目录可能存在                          | 76                                                                                                                 | 卸载 → 租约 → ids 一致 → 新库改名为 `.aborted-<txid>`（ids 缺失时只改名纯骨架）→ 撤销登记，exit 1 |
| 第 3 步 `renaming`，**改名未发生**                                                         | 原路径是源目录（inode 一致）                            | 76                                                                                                                 | 跳过改名步骤，执行 R-A，exit 1                                                                    |
| 第 3 步 `renaming` / `backed-up`，**改名已发生**                                           | 备份存在、原路径不存在                                  | 76                                                                                                                 | （有 `.modes` 时先恢复权限）→ NOREPLACE 改回原名（inode 不变）→ R-A，exit 1                       |

转换过程中的中断：第 1–13 步收到 SIGINT / SIGTERM / SIGHUP 时，记录信号并向所有受跟踪的 worker 进程组发 SIGTERM（worker 结局变为未知 ⇒ 回滚）。回滚完成后 exit 130（INT）或 143（TERM / HUP），文案写明「已回滚」或「回滚未完成 + 剩余项 + `--abort`」。回滚开始后不再响应第二个信号。第 14 步期间信号被延后处理；提交完成后照常收尾并 exit 0。转换锁的持有进程在独立进程组中，终端 Ctrl-C 不会在回滚期间释放这把锁；本进程退出时管道关闭，锁随之释放，不会有孤儿进程一直持锁。

## 5. 偏差（相对方案字面）

1. **git 不走 tree worker，用 `runBounded` 单独监督**：每条 git 命令都在独立进程组中运行，有截止时间，到期 KILL 整组，并以完整的 /proc 扫描确认组已空（扫描不完整即视为不干净 ⇒ `git-uncertain`）。监督强度与 worker 等价，省掉一层进程。
2. **会话 worker 在 convert.mjs 自己的入口** `node convert.mjs __convert-work <op>`。V6 可以改为 `helper.mjs __convert-work`，只需替换 `ctx.convertArgv`。
3. **占用扫描不读 fdinfo**：fd 符号链接已经给出路径，fdinfo 里没有路径信息（建议方案侧补记）。同 uid 但读不到 /proc 的进程按用户裁定（§9）列出并要求确认；僵尸与扫描中途退出、exec 的进程经最多 3 轮 × 100 ms 复查排除。
4. **`applyRootMeta:false`**：work 根目录保持 vault 布局的 0700，不套用原根目录的 mode / mtime。这样原根目录没有 u+w 时，第 9 步写 `.pi/settings.json` 也不会失败。转换后与原目录的允许差异因此是：根目录的 mode / mtime，加上 `.pi/settings.json` 及其 `.bak`。
5. **`--abort` 成功时 exit 1**：按 §1.6 原文「打印『已回滚』（exit 1 或 130）」实现。`--resume` 的拒绝（phase < synced、基线不符、登记项不属于本次、原路径被占用）统一用 76「状态冲突」，方案没有指定退出码。
6. **嵌套仓库的 core.worktree**：根仓库按 §1.3.1 原文，配置了就拒绝。嵌套仓库（子模块在 `.git/modules/x/config` 里固定写一个相对路径的 core.worktree）只在它指向树外、或者不等于自身 checkout 时才拒绝，否则所有带子模块的项目都会被拒。HEAD / status 的一致性比较与 fsck 只针对根仓库。
7. **状态文件的额外字段**：`originReal`、`vault{dir,mnt}`、`opts`、`layoutAttempted`、`linking`、`link`、`ids.cipher`、`updatedAt`；`.txn` 里另有 `.base` / `.hashes`（方案只写了 `.json` / `.modes`）。这些都是恢复判定需要的身份信息。
8. **`--private`**：第 2 步认领时就把 `private:true` 写进条目（pending 期间该库本来就不可用）；转换本身用普通挂载，与方案一致。
9. **删除我们自己建的链接**：方案写的是直接 unlink。这里先 NOREPLACE 改名到 `.pi-secure-unlink-<txid>`，复核后再 unlink，竞态窗口只剩这个私有名字。
10. **（r3.1 撤销）权限恢复对不上的条目**：首版只给警告；r3.1 M9 改为「回滚不完整」、非零退出、保留状态与 `.modes`。数据仍照常改回原名（把数据放回原位不依赖权限），再次 `--abort` 在原路径上幂等重试恢复。
11. **相对路径的源目录**：启动器会先 `cd /`，所以 convert 只接受绝对路径或 `~/` 开头的路径；`ctx.cwd` 由 V6 传入原 cwd 后才支持相对路径。
12. **tree.mjs 零改动**：V2 的 API 已经够用；r3.1 使用 V5 新增导出的 `reapGroup`（未改其函数体）。
13. **git 加固（r3.1 M6）**：复用 worktree-diff 的做法而不 import `src/git/`（convert.mjs 零依赖、纯 ESM，常量 `GIT_EMPTY_TREE` / `GIT_DRIVER_SCAN_REGEXP` / 驱动名正则与 `src/git/diff.ts` 逐字一致）：最小 env（PATH 固定 `/usr/bin:/bin`，`GIT_CONFIG_GLOBAL=/dev/null`、`GIT_CONFIG_NOSYSTEM=1`、`GIT_ATTR_NOSYSTEM=1`、`GIT_NO_LAZY_FETCH=1` 等），每条命令带 `--no-optional-locks -c core.fsmonitor=false -c core.hooksPath=/dev/null -c core.attributesFile=/dev/null`，每个仓库再加 `--attr-source=<空树>` 与全部 filter/diff 驱动命令槽清空；驱动名不安全或无法读取 ⇒ `git-uncertain`。用到的命令只有 `rev-parse`、`config --get`、`config --get-regexp`、`worktree list`、`fsck`，都不写 index；`status` 比较删除——副本与备份的字节一致性（含 `.git`）已由 tree verify 逐文件证明。
14. **step-3 改名失败退出码**：身份不符（`parent-identity` / `parent-path` / `source-identity` / `identity-mismatch` / `parent-path-changed`）⇒ 76；其余确证未改动（`unchanged`）⇒ 65；结局未知 ⇒ 74（`renameExit`；身份优先，因为被换掉的源目录是状态冲突）。
15. **会话 partial**：§2.2#4 的闭包预算 partial 仍只进报告；但单个会话文件或 memory 文件未完整复制（`partial` / `conflict`）⇒ 第 10 步失败（M10）。

## 6. 残留

- **（已由用户裁定，见 §9）不可读的同 uid 进程**：本机常驻 `sd-pam`（pid 1276，systemd 用户会话）与本用户的 `sshd` 会话进程，它们的 `/proc/<pid>/cwd`、`fd/`、`maps` 对同 uid 也不可读。r3.1 首版按 M8 一律 75，会让 convert 在此类机器上不可用；用户裁定改为「列出后要用户确认」（§9）。残留：确认是用户的判断，工具无法证明这些进程不碰该目录。
- **I1 的窗口（同 uid 定向竞态，威胁模型外）**：`rmdirEmptyOwn` 的 lstat→rmdir（只对本 txid 创建且为空的挂载点，与 V2 探针同口径：可能删除被换入的空目录）、`removeOwnLink` 的复核→unlink（只在私有名 `.pi-secure-unlink-<txid>` 上）不是原子操作。新库不再删除，递归删除代码已移除。
- **I4 的前提**：占用扫描结束到冻结之间，如果有进程打开源目录并写入，第 12 步按纳秒精度比较 ctime / size / mtime 可以发现；但同一个内核 tick 内的碰撞（V2 §9）只可能来自并发写入者，而占用检查排除了良性写入者。不可转储的同 uid 进程无法检查（偏差 3）。
- **会话 worker 的进度粒度**：发现阶段（读会话头）没有进度行，异常大的会话目录可能触发 60 s 停滞 ⇒ 回滚（fail closed，不会丢数据）。
- **`.txn` 中的元数据**：`.base` / `.hashes` / `.modes` 在库外以明文保存相对路径、大小、mtime 以及**内容 sha256**，直到完成或回滚后删除。备份本身就是同目录下的明文，这些信息不会超出备份已有的暴露面（R30 的扩展）。
- **`.aborted-<txid>` 由用户删除**：回滚后同级留下的 `<名字>.aborted-<txid>`（密文 + 元数据，挂载点副本在假挂载 / 未清空时也会留下）需要用户核对后自行删除；`status` 目前不列出它们（V6 可考虑）。
- **owner guard 的粒度**：watcher 每 0.25 s 轮询一次 PPid（纯 sh 内建 + `sleep`），编排者死亡后 worker 最多再运行约 0.25 s；guard 自身被单独 SIGKILL（而编排者存活）时，worker 仍由 superviseWorker 的停滞看门狗与进程组清理兜底。
- **测试覆盖边界**：单测用假端口（registry / 布局 / 挂载）；2 例真 gocryptfs 测试走真实 FUSE 的拷贝、读回校验、git、屏障与回滚卸载（回滚后新库改名为 `.aborted-<txid>`），但口令用 passfile 代替 TTY；1 例真子进程：编排者在拷贝中被 SIGKILL，断言 worker 组自行消失后 `--abort` 完整回滚。helper 端口的真实装配、TTY 交互与 kill -9 的进程级恢复属于 V6 / V7（§7.2-3/4）。真实 getfattr 输出未验证（本机未装 attr，V7 XC7）。
- **V6 待办**：`getVaultEntry` 原始条目读取、`initCipher`、`leaseState` 的装配；`status` 调用 `listInterruptedConverts` + `formatInterruptedLine`；`resolveVault` 对 pending 的拒绝（§3.5）；USAGE 加上 `CONVERT_USAGE`；相对路径需要原 cwd。

## 9. 用户裁定：不可读进程确认（2026-10-24 11:09）

**新增残留**：

- **tree.mjs 内部的信号**：`superviseWorker` / `renameNoReplace` 对**它们自己刚 spawn 的**子进程组的 TERM/KILL 仍用 V2 的 `pgidStillOurs`（tree.mjs 只许新增 export，不改函数体）。这些信号的对象来自进程内的 spawn，不来自状态文件，不受 R2-B2 的篡改路径影响；convert.mjs 自己发出的组信号全部经 `proveGroupOurs`。
- **pid 精确的例外（均为对自己尚未回收的子进程按 pid 发信号，pid 不可能被复用）**：持久化 worker 身份失败时 `c.kill("SIGKILL")`（convert.mjs:1399，见 R2-B2）；转换锁 flock 持有进程握手超时 / 释放超时时的 `child.kill("SIGKILL")`（convert.mjs:1125、1158，该进程不在任何进程组信号路径上）。组信号（`process.kill(-pgid, …)`）在 convert.mjs 里只剩 `signalGroupIfOurs` 内的一处（convert.mjs:415）。
- **`mv` 子进程不带 txid**：`renameNoReplace` 的 `mv` 由 tree.mjs 启动，环境里没有 txid，中断时不会收到 TERM（它们短且有 tree.mjs 自己的期限）。
- **未挂载时的 9/10 步复核**：新库未挂载时无法重新观察明文侧的 settings 文件与 state 目录，`--resume` 只能依据落盘的证据 + cipher 身份 + 屏障证据。
- **冻结 → 记录 `modesCount` 之间崩溃**：没有条目数对照，只能要求 `.modes` 非空且有唯一根记录。
