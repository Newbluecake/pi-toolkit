## 4. 偏离与说明

1. **relocate 在插件侧也判为 locked**：§4 只写了 pending。启动器在迁址完成前拒绝打开这种库，所以里面跑的会话本来就不是合法的加密会话；按「拿不准就拒绝」处理，比方案更严。
2. **改动了 archive.mjs**（不在方案写的 V6 文件范围内）：只是把 `relocateVault` 的四步提取成 `runRelocateSteps` 并导出，让私有库在 ns 内复用同一段经过安全评审的 fd 锚定代码，避免抄一份 payload。`relocateVault` 的行为不变（准入、phase 守卫、清标记、卸载都没动），V5 的 120 例照常全过。私有库拒绝文案改为指向新入口。
3. **私有库迁址的 phase 粒度更粗**：标记在 ns 外的 settings 锁内写入——开始前写 `sessions`、成功后写 `synced`，然后删除。各步本身可重入，崩溃后从「标记仍在」重做，与 §3.4「下次入口从实际状态继续」一致。ns 内不写 settings。
4. **拒绝放在命令层，而不是 `resolveVault`**：原因见清单 #11。
5. **原 cwd 取物理路径**（`pwd -P`）：相对路径按内核解析的方式落地；cwd 已被删除时变量为空，helper 忽略它，相对路径会按 `/` 解析，或由引擎报错。
6. **`pendingRefusal` 对未知 op 前缀**（V0 允许写任意 `<op>:`）的文案回落为 convert 的命令提示。

## 5. 残留

- （已按评审 #1 关闭）非法事务键不再让条目消失：保险库保留并判 locked，见 §7 #1。
- `__mount` 的事务豁免凭证是「当前登记里的 pending / relocate.txid」：它不是秘密，同 uid 进程手工带上正确的 `--txn` 仍可直调内部入口——属既定威胁模型之外（V2 裁定）；检查的作用是让事务标记在入口处生效，而不是认证调用方。
- origin 拼写表是尽力而为：用户如果把原路径的符号链接换成了一个新的明文目录，普通会话里提到该路径的 bash 命令仍会被拦（误报方向）；插件按进程冻结，已在运行的 pi 需要重启才会认得新的 origin（§1.7 原文）。
- `.aborted-<txid>` 只在缺省父目录和已登记库的父目录里查找；convert 用过自定义 `--path`、登记又已撤销时，非空挂载点副本若留在其他父目录，status 不会列出。convert `--abort` 本身会打印这些路径。
- convert 的 TTY 交互（键入名字确认、gocryptfs 口令、master key 输出）、`--resume`/`--abort` 的真实 kill -9 恢复、普通库 `init --fix-settings` 的真实端到端，属于 V7（§7.2）。本包只用真实 gocryptfs 覆盖了私有库 setup 模式迁址，以及「已挂载 ⇒ 76」。
- 本机没有 `getfattr`（V4 XC7 已记录），在本机交互式 `pi-secure convert` 会在前置检查返回 69。

## 8. 安全复审第 2 轮处置（#1/#3/#4 闭合；#2 的新 Blocker，主会话裁定）

**问题**：第 1 轮为 #2 新增的 `removeInitSkeleton` 先算 `dirOk`/`mntOk`，再按绝对路径 unlink `mount.lock`/`mount.lease`/`work`/`state`。检查与 unlink 之间，一旦换入非空文件、或把已检查的父目录换成指向外部的链接，就会删掉不属于本次的数据（违反 I1/I3）。
