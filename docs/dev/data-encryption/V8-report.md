## 1. A：挂载点位置 / 祖先链检查前移到第 0 步

**问题**（V7 观察）：

- convert：挂载点位置规则（`positionProblems`）和祖先链规则（`mntAncestorProblems`）都在第 2 步 `createLayout` 里执行。祖先链不合规（例如 `$HOME` 组可写）时，用户已经看完计划、键入名字、通过认领，才得到 78，之后再回滚。

## 4. 残留与观察

1. **`.convert.lock` 早于第 0 步**（§1）：convert 被拒时可能留下这个空锁文件；import 的位置拒绝已前移到锁之前，零写入。
2. **import 的早检读取配置时不持锁**：这只是一次只读的早期拒绝；设置文件是原子写入（tmp+rename），读到的总是完整版本。配置不可读或非法时跳过早检，交给锁内原有检查报告。锁内会用同一个函数复核，发布时还会再查一次祖先链。
3. 验收文档里的 K10、M3 用到测试缝（`PI_SECURE_TEST_SEAMS=1` + `CONVERT_STOP_AT`），只为复现精确的暂停点或中断点，文中要求用完立即 unset。K2 另给出大文件这种不依赖测试缝的办法。
4. 本机原先没有 `getfattr`（V4 XC7）。真机执行 K 节前需要 `sudo apt install attr`，否则 convert 报 69。验收前置 K0-3 已写明。

5. **全量运行中暴露的两个既有测试抖动（只改测试，已修）**：
   - `launcher-v6-wiring`「lost claim after createLayout …」第 3 段：测试先 `rmSync` 掉记录过身份的 `<dir>`，再建一个「外来」目录。刚释放的 inode 号可能被新目录立即复用，于是与记录的 (dev, ino) 相同，被当作本次骨架搬走（预期 `moved: []`，实得 1 项）。单独重跑 3/3 通过。修法：把原目录改名为 `<dir>.recorded` 保留下来，不让 inode 被复用；产品逻辑不变。
   - `launcher-convert`「M2: paused at 13:after …」：启动器先写出「测试缝：convert 在第 N 步暂停（pid P）」再自我 SIGSTOP。`waitStopped` 观察到 T 状态时，pty 读端可能还没把这行交给测试。修法：断言前最多等 3 s 轮询这行文字（V7 新增的辅助函数 `pauseThenContinue`）。
