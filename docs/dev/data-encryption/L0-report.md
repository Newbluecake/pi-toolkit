## 2. 旧布局兼容行为（§L.3，已拍板 Q-L0）

- **识别**：条目含 `link` 键（值不校验）⇒ legacy；或不含 `mnt` 且 `<dir>/mnt` 是目录（helper 默认与插件侧都用真实 lstat 探针；parity 用例经注入探针钉住）⇒ legacy。显式 `mnt` 总是赢过磁盘上的 `<dir>/mnt`。
- **允许**：`status`（`layout legacy` + mnt 列 + 迁移指引两行）、`lock`（共享 `finalize`，卸载旧挂载点 `<dir>/mnt`；未挂载 ⇒ 0「未挂载」）。`export` 由后续包实现，L0 只保证判定函数能识别旧布局（`deriveLegacyVault`/`physicalPaths` legacy 分支）。
- **拒绝（78）**：`unlock`、`run`、`run --private`（未实现，天然不可达）、`init --fix-settings`、对已登记旧库的重 `init`。文案逐字采用 §L.3：「保险库 X 使用旧布局（挂载点 `<dir>/mnt`）。没有真实数据：pi-secure 登记项与目录删除后重新 init；有真实数据：pi-secure export X <文件> 后 pi-secure import <文件> <新名字>（新布局，会话与 sessionDir 自动迁址），确认无误再删除旧库。」拒绝发生在问口令与 pi 定位之前（`existsSync(calls.log)`/pi-record 均为假的断言钉住）。
- **插件**：旧库 domain 判定保持旧行为（`mntReal = <root>/mnt`）：cwd 在旧挂载点下且挂载着 ⇒ secure；未挂载 ⇒ locked；普通会话经旧链接的字面量/canonical 路径访问旧库 ⇒ D4 拦截（canonical 解析进 `<root>`；字面量 `mnt` 拼写对 legacy 即 `<dir>/mnt`，仍在 `root` 之下）。
- **不做就地迁移**（§L.3 拍板）：正确的迁址引擎是 convert 方案的 export→import。
