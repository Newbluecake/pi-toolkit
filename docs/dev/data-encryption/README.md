## src/secure/

`src/secure/` — encrypted session vaults over gocryptfs (design, rulings D1–D9/Q1–Q2 and the full residual list: `docs/dev/data-encryption/plan.md` r4; reports P0–P2 incl. security-review fixes). Two halves sharing a CONTRACT, never an import (parity fixture `tests/fixtures/secure-contract-parity.json`, never regenerate). **Launcher** `bin/pi-secure` (thin bash entry: locate helper via `readlink -f`, Linux check, `ulimit -c 0`, `umask 077`, `cd /`) + `bin/helper.mjs` (pure Node, zero deps; npm `bin` entry; installed by the `ln -s …/src/secure/bin/pi-secure ~/.local/bin/pi-secure` line `/secure status` prints): `init <name> [--path|--fix-settings]` / `unlock` / `lock [--lazy]` / `status [<name>]` / `run <name> [-C <subdir>] [pi args…]`. The vault password is typed by the user straight into gocryptfs on the TTY — the toolkit never reads, stores or passes it; `init` requires a real TTY and never passes `-q`, so the master key prints exactly once in the terminal (Q1). `run` re-parses args through pi's own `dist/cli/args.js` `parseArgs` (structural self-check, fail closed — C4 pins drift): `--session-dir` present (even `""`), `--no-extensions`/`-e`/`--export`, and unknown dangling `session-dir`/`session`/`fork` flags are rejected before any mount or password prompt; `--session <path>` must resolve under `<state>/sessions/` (re-checked physically after mount); `--fork`/`@file` copy INTO the vault; `--no-session` is allowed. Exit codes: 64 args rejected · 66 unknown vault · 69 prerequisites missing · 73 mount.lock timeout · 75 finalize budget exhausted / hard fallback (`process.exit(75)`) · 76 vault busy · 77 three password misses (1s/2s/4s backoff) · 78 config error (bad settings, sessionDir conflict, `enabled:false`). Both `run` (after pi exits) and `lock` end in the same bounded `finalize(10s)`: `/proc/*/cwd` occupancy scan, `flock`-guarded `fusermount3 -u` as ONE detached process group, SIGKILL without waiting at the deadline (D-state leftovers are residual R19), and an unref'd `budget+500ms` timer hard-exits 75. Vault registration (`pi-secure init`) and the plugin's `persistSettingOverride` share one settings-file lock (`settings-lock.ts`: whole read→merge→tmp→rename under `flock(2)` on `<settings dir>/.pi-subagent.json.lock`, atomic writes, symlink/non-regular/foreign-owner fail-closed; the only lockless exception is a system without flock). **Private mode** (`run <name> [--private|--no-private]` — recognized only right after the name, default `secure.vaults.<name>.private`; plus `init --private` / `unlock --global` / `lock --lazy|--kill`, L0+N0–N4): the plaintext mount lives only in a per-run private mount namespace (outside processes see just the two sentinels; another vault globally mounted ⇒ refuse, Q10), serialized by a kernel-held `mount.lease` flock (shell-opened fd 9 handed on only via explicit stdio slot 9 to gocryptfs `-fg` and the inner unshare→pi) plus a `private.json` v3 instance record deleted only from outside the ns via the release protocol; unreadable same-uid processes are judged by ppid lineage (private-plan §3.3 r3.2, scan-poison fix — only provably in-lineage ones still fail the scan); termination authority needs proven membership (unprovable holders only reported, never killed) and the web hub is never spawned inside the ns (`spawnHub` hard gate + one-time notify + `agent.nospawn.v1` cap; the three-state gate treats unknown as in-ns, fail-safe) — design `docs/dev/data-encryption/private-plan.md`, user-facing plan §2.8. **Convert / migrate** (convert-plan r3/r3.1, packages V0–V8): `pi-secure convert <dir> [<name>] [--path …] | --resume|--abort <name>` (original dir becomes a read-only sibling backup, never deleted; original path → symlink to `<mnt>/work`), `export <name> <file.tar>` (unmounted, ciphertext-only `pi-secure-vault/2`), `import <file.tar> <name> [--path …] [--verify-password] | --resume|--abort <name>`, and the `init <name> --fix-settings` relocation entry; engines live in `bin/{convert,archive,tar,tree,sessions}.mjs` (convert gets helper capabilities only through injected ports); the `init` body, the `--private` command bodies (record subcommands, external `lock`, `__mount-work`, `__ns-root`) and the in-ns finalize steps live in `bin/{init,private,finalize}.mjs` (#56 ⑩-S) — they import their primitives from `helper.mjs` and are loaded ONLY through lazy `await import("./x.mjs")` from helper's dispatcher (a copy of `helper.mjs` alone must still run every other command; the exported helper API never moved, so tests keep driving it as `H.x`), and mount-point position/ancestor rules are judged at step 0 before any prompt, claim or password (V8). User-facing summary — flow, `status` lines, exit codes, `--resume`/`--abort`, `.aborted-<txid>`/`.init-failed-*` cleanup, residuals R26–R28/R30/R32/R33 — is plan §2.9 「转换与迁移」; real-machine checklist acceptance.md K–M.
**Plugin guards**: `initSecureDomain()` is the FIRST statement of `activate()` (`src/index.ts`, before any settings read), freezing the verdict per process on `Symbol.for("pi-subagent:secure-domain")` — env `PI_SECURE_VAULT` ?? cwd match (whole vault dir, not just `mnt/`) + mount state ⇒ secure / locked / plain; `/reload` never re-judges, so a newly registered vault needs a pi restart (`/secure status` says so). secure ⇒ `TMPDIR=<state>/tmp`, `ARMORY_MEMORY_ROOT=<state>/memory`, `PI_SECURE_SESSION=1`, `PI_SECURE_VAULT` (so a nested `pi` joins the same domain). `loadSettings` (both entry points) clones-then-overrides `bashJobs.dir`/`workflow.journalDir` into `<state>` and turns D8 features off (`fabric.crossSession`, `externalAgents.droid`, `feishuNotify`; schedule additionally: the run-mode matrix resolves a secure/locked domain to mode `secure` — every action `E_SECURE`, never arms, no store/hub key/directory). `legacyConsultForkDir()` (`src/runtime/legacy-consult-forks.ts`, legacy since #40) resolves the `<state>/cache/consult-sessions` root, which is now used only to sweep old fork files and is never created again (the vault layout's `consult` entry in `STATE_SUBDIRS` stays for old vaults); child sessions land in `SessionManager.create(cwd, <state>/sessions/default)`; cross-domain resume and `session_before_switch` are cancelled. `wireSecureGuards` (pre-guard, registered before every other handler — first `handled`/`block`/`cancel` wins) enforces D2 (worktree isolation rejected; workflow `worktreeAvailable` false), D3 (secure write/edit confined to strictly below `mnt/work`/`mnt/state` — sentinel paths and `mnt/` root entries refused, symlink escape caught) and D4 (plain-domain read/write/edit/grep/find/ls + best-effort bash command-text scan stay out of every vault; `user_bash` is the user's own action, unchecked); a secure process re-checks the mount on EVERY `tool_call` and `input`, so a mid-session unmount flips the session to LOCKED (`secure:locked` status key) instead of letting the write zone degrade to plaintext. LOCKED ⇒ all input `handled`, all tools blocked, `user_bash` refused, notify with the fix (e.g. `pi-secure run acme -C sub`), no auto-shutdown (`/quit` works); `--no-session` sessions skip the session-file/dir checks but not the cwd/mount ones. `hubSafeEnv` (`env.ts`, zero imports, also boundary-whitelisted for the hub) strips `PI_SECURE_*` and restores/deletes `TMPDIR`/`ARMORY_MEMORY_ROOT` per `PI_SECURE_ORIG_ENV`, wired at `spawnHub` (`web-hub/agent/launcher.ts`) and the hub spawn supervisor's `forkInto` env loop — a hub spawned from a secure session cannot misfreeze normal web sessions. `/secure status` (read-only, post-guard, main session only; web command policy `secure status` = allow, anything else = deny) reports the verdict, lock reason, per-vault mount state, the D5 traffic-record check and the launcher install hint. A missing settings file, an absent `secure` section and `enabled:false` keep the command table, hooks, `process.env` and settings byte-identical (golden `tests/fixtures/secure-off-golden.json`, never regenerate); a present-but-unreadable/corrupt section deliberately surfaces `secure:invalid` + one warn (security-review #2). Gates: `tests/secure/**` (launcher-helper/cli/fuse, domain, guards, guard-points, settings-override, settings-lock, config-parity, off-golden), `tests/conformance/secure-gocryptfs.test.ts` (self-gating C1–C5, run before any pi peer or gocryptfs bump) and the probe `scripts/dev/secure-probe.sh`. Accepted residuals (plan §5 — hardening, NOT a no-plaintext guarantee): web-hub/LAN/Feishu plaintext copies incl. uploads, Feishu durable-request bodies, outbox content and spawn stderr logs (R12); swap/hibernate and apport core dumps, warn-only (R2/R3); same-uid `/proc/<pid>/mem` and terminal/tmux scrollback incl. the printed master key (R16); bash writing outside the vault best-effort only (R8); bypassing the launcher with raw `pi` (R6) and pi-native `/debug` `/export` `/share` `/copy` (R4); crashes.json (R1); pre-migration plaintext originals (R17).

## 设置文件协议（#54）

设置文件改名 `pi-subagent.json` → `pi-toolkit.json` 并跟随 agentDir（设计：`docs/dev/settings-rename/plan.md` r3）。secure 侧的四条不变式：

- **锁名固定**：`<设置目录>/.pi-subagent.json.lock` 永不随文件名变——新旧插件、新旧 launcher 必须争同一把锁（I7 例外项）。
- **launcher 按 agentDir 解析、新名优先**：helper.mjs 镜像 `resolveAgentDir` + `resolveSettingsLocation`（含 `~/.pi/agent` 继承回退）；两个名字都没有时 launcher 仍默认旧名（拍板②）。launcher 只补完崩溃遗留的迁移中间态（`healSettingsFileLocked`），不发起迁移。pi 与 launcher 必须在同一套环境变量下运行；`status` 在非默认 scope 时打印 `[agentDir: env]` / `[inherited]` 后缀。
- **S6b fail-closed**：新旧两份文件同时存在且 `secure` 段不一致时，domain 置 `secure:invalid`，launcher `run`/`unlock` 以 78 退出——宁可报错也不静默只用一份。
- **agentDir-in-vault fail-closed**：`PI_CODING_AGENT_DIR` 与任一已登记保险库的 `dir`/`mnt` 相互嵌套 ⇒ domain 判 locked、`status` 打印 `!` 行、`run`/`unlock`/`init` 退出码 78（登记表不能藏进它自己描述的保险库）。

另：`/secure status` 探测 PATH 上过旧的 pi-secure（realpath 后在它的 helper.mjs 里找新名标记），旧版且已迁移时给出改指本检出的 `ln -sf` 命令；pi-secure 与插件同版发布，安装链接必须指向同一检出。
