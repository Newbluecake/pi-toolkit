## src/secure/

`src/secure/` — encrypted session vaults over gocryptfs (design, rulings D1–D9/Q1–Q2 and the full residual list: `docs/dev/data-encryption/plan.md` r4; reports P0–P2 incl. security-review fixes). Two halves sharing a CONTRACT, never an import (parity fixture `tests/fixtures/secure-contract-parity.json`, never regenerate). **Launcher** `bin/pi-secure` (thin bash entry: locate helper via `readlink -f`, Linux check, `ulimit -c 0`, `umask 077`, `cd /`) + `bin/helper.mjs` (pure Node, zero deps; npm `bin` entry; installed by the `ln -s …/src/secure/bin/pi-secure ~/.local/bin/pi-secure` line `/secure status` prints): `init <name> [--path|--fix-settings]` / `unlock` / `lock [--lazy]` / `status [<name>]` / `run <name> [-C <subdir>] [pi args…]`. The vault password is typed by the user straight into gocryptfs on the TTY — the toolkit never reads, stores or passes it; `init` requires a real TTY and never passes `-q`, so the master key prints exactly once in the terminal (Q1). `run` re-parses args through pi's own `dist/cli/args.js` `parseArgs` (structural self-check, fail closed — C4 pins drift): `--session-dir` present (even `""`), `--no-extensions`/`-e`/`--export`, and unknown dangling `session-dir`/`session`/`fork` flags are rejected before any mount or password prompt; `--session <path>` must resolve under `<state>/sessions/` (re-checked physically after mount); `--fork`/`@file` copy INTO the vault; `--no-session` is allowed. Exit codes: 64 args rejected · 66 unknown vault · 69 prerequisites missing · 73 mount.lock timeout · 75 finalize budget exhausted / hard fallback (`process.exit(75)`) · 76 vault busy · 77 three password misses (1s/2s/4s backoff) · 78 config error (bad settings, sessionDir conflict, `enabled:false`). Both `run` (after pi exits) and `lock` end in the same bounded `finalize(10s)`: `/proc/*/cwd` occupancy scan, `flock`-guarded `fusermount3 -u` as ONE detached process group, SIGKILL without waiting at the deadline (D-state leftovers are residual R19), and an unref'd `budget+500ms` timer hard-exits 75. Vault registration (`pi-secure init`) and the plugin's `persistSettingOverride` share one settings-file lock (`settings-lock.ts`: whole read→merge→tmp→rename under `flock(2)` on `<settings dir>/.pi-subagent.json.lock`, atomic writes, symlink/non-regular/foreign-owner fail-closed; the only lockless exception is a system without flock). **Private mode** (`run <name> [--private|--no-private]` — recognized only right after the name, default `secure.vaults.<name>.private`; plus `init --private` / `unlock --global` / `lock --lazy|--kill`, L0+N0–N4): the plaintext mount lives only in a per-run private mount namespace (outside processes see just the two sentinels; another vault globally mounted ⇒ refuse, Q10), serialized by a kernel-held `mount.lease` flock (shell-opened fd 9 handed on only via explicit stdio slot 9 to gocryptfs `-fg` and the inner unshare→pi) plus a `private.json` v3 instance record deleted only from outside the ns via the release protocol; unreadable same-uid processes are judged by ppid lineage (private-plan §3.3 r3.2, scan-poison fix — only provably in-lineage ones still fail the scan); termination authority needs proven membership (unprovable holders only reported, never killed) and the web hub is never spawned inside the ns (`spawnHub` hard gate + one-time notify + `agent.nospawn.v1` cap; the three-state gate treats unknown as in-ns, fail-safe) — design `docs/dev/data-encryption/private-plan.md`, user-facing plan §2.8. **Convert / migrate** (convert-plan r3/r3.1, packages V0–V8): `pi-secure convert <dir> [<name>] [--path …] | --resume|--abort <name>` (original dir becomes a read-only sibling backup, never deleted; original path → symlink to `<mnt>/work`), `export <name> <file.tar>` (unmounted, ciphertext-only `pi-secure-vault/2`), `import <file.tar> <name> [--path …] [--verify-password] | --resume|--abort <name>`, and the `init <name> --fix-settings` relocation entry; engines live in `bin/{convert,archive,tar,tree,sessions}.mjs` (convert gets helper capabilities only through injected ports); the `init` body, the `--private` command bodies (record subcommands, external `lock`, `__mount-work`, `__ns-root`) and the in-ns finalize steps live in `bin/{init,private,finalize}.mjs` (#56 ⑩-S) — they import their primitives from `helper.mjs` and are loaded ONLY through lazy `await import("./x.mjs")` from helper's dispatcher (a copy of `helper.mjs` alone must still run every other command; the exported helper API never moved, so tests keep driving it as `H.x`), and mount-point position/ancestor rules are judged at step 0 before any prompt, claim or password (V8). User-facing summary — flow, `status` lines, exit codes, `--resume`/`--abort`, `.aborted-<txid>`/`.init-failed-*` cleanup, residuals R26–R28/R30/R32/R33 — is plan §2.9 「转换与迁移」; real-machine checklist acceptance.md K–M.
**Plugin guards**: `initSecureDomain()` is the FIRST statement of `activate()` (`src/index.ts`, before any settings read), freezing the verdict per process on `Symbol.for("pi-subagent:secure-domain")` — env `PI_SECURE_VAULT` ?? cwd match (whole vault dir, not just `mnt/`) + mount state ⇒ secure / locked / plain; `/reload` never re-judges, so a newly registered vault needs a pi restart (`/secure status` says so). secure ⇒ `TMPDIR=<state>/tmp`, `ARMORY_MEMORY_ROOT=<state>/memory`, `PI_SECURE_SESSION=1`, `PI_SECURE_VAULT` (so a nested `pi` joins the same domain). `loadSettings` (both entry points) clones-then-overrides `bashJobs.dir`/`workflow.journalDir` into `<state>` and turns D8 features off (`fabric.crossSession`, `fabric.threads`, `externalAgents.droid`, `feishuNotify`, `memory.jev.enabled`, `reflex` incl. `reflex.drafts` — #25 BA §4.6, offline draft scripts never enter an encrypted domain; schedule (interval P1): both settings loaders force `schedule.enabled=false` before actual activate registration, even with explicit true — no tool/command/prompt/status/cap/store/hub key/directory; the run-mode matrix and runtime mount rechecks retain `E_SECURE` as defense in depth). `legacyConsultForkDir()` (`src/runtime/legacy-consult-forks.ts`, legacy since #40) resolves the `<state>/cache/consult-sessions` root, which is now used only to sweep old fork files and is never created again (the vault layout's `consult` entry in `STATE_SUBDIRS` stays for old vaults); child sessions land in `SessionManager.create(cwd, <state>/sessions/default)`; cross-domain resume and `session_before_switch` are cancelled. `wireSecureGuards` (pre-guard, registered before every other handler — first `handled`/`block`/`cancel` wins) enforces D2 (worktree isolation rejected; workflow `worktreeAvailable` false), D3 (secure write/edit confined to strictly below `mnt/work`/`mnt/state` — sentinel paths and `mnt/` root entries refused, symlink escape caught) and D4 (plain-domain read/write/edit/grep/find/ls + best-effort bash command-text scan stay out of every vault; `user_bash` is the user's own action, unchecked); a secure process re-checks the mount on EVERY `tool_call` and `input`, so a mid-session unmount flips the session to LOCKED (`secure:locked` status key) instead of letting the write zone degrade to plaintext. LOCKED ⇒ all input `handled`, all tools blocked, `user_bash` refused, notify with the fix (e.g. `pi-secure run acme -C sub`), no auto-shutdown (`/quit` works); `--no-session` sessions skip the session-file/dir checks but not the cwd/mount ones. `hubSafeEnv` (`env.ts`, zero imports, also boundary-whitelisted for the hub) strips `PI_SECURE_*` and restores/deletes `TMPDIR`/`ARMORY_MEMORY_ROOT` per `PI_SECURE_ORIG_ENV`, wired at `spawnHub` (`web-hub/agent/launcher.ts`) and the hub spawn supervisor's `forkInto` env loop — a hub spawned from a secure session cannot misfreeze normal web sessions. `/secure status` (read-only, post-guard, main session only; web command policy `secure status` = allow, anything else = deny) reports the verdict, lock reason, per-vault mount state, the D5 traffic-record check and the launcher install hint. A missing settings file, an absent `secure` section and `enabled:false` keep the command table, hooks, `process.env` and settings byte-identical (golden `tests/fixtures/secure-off-golden.json`, never regenerate); a present-but-unreadable/corrupt section deliberately surfaces `secure:invalid` + one warn (security-review #2). Gates: `tests/secure/**` (launcher-helper/cli/fuse, domain, guards, guard-points, settings-override, settings-lock, config-parity, off-golden), `tests/conformance/secure-gocryptfs.test.ts` (self-gating C1–C5, run before any pi peer or gocryptfs bump) and the probe `scripts/dev/secure-probe.sh`. Since #27 the secure vitest project additionally fail-fasts on a dirty machine (`tests/secure/preflight.ts`: any `fuse.gocryptfs` mount — including your OWN vault —, a concurrent secure run, or a symlinked TMPDIR aborts before the suites run; fix the environment and re-run, never triage it as flake) and runs standalone via `npm run test:secure` (see `docs/dev/test-speed/README.md`). ## 挂载拼写契约与威胁模型残留（#28）

- **挂载拼写契约**：普通 launcher（非 private 模式）以挂载前一次性算出的物理 cipher 路径（`physicalPaths(v).realCipher`，即 `realpath(<dir>)/cipher`）与物理挂载点传给 gocryptfs，与 private 模式一致；mount 归属判定（`source === realCipher`）不放宽——两种模式、插件 `judgeVaultMount` 与 launcher 复检使用同一物理口径。设计：`docs/dev/secure-symlink/plan.md`（r3）。
- **威胁模型残留（R2，检测边界）**：fsname（mountinfo source）只是挂载者自填的标签，内核不校验。**cipher 的物理祖先可被可写父目录的属主替换 ⇒ 检测不到**（R2，realpath 串不变、fsname 相同 ⇒ 判 mounted）。它只影响可用性与目录级完整性，机密性由挂载点祖先链规则、cipher 的 0700 与口令兜住；该缺口在本修复前就存在。用户侧建议：把 `<dir>` 放在只有本人和 root 可写的链下。同在 `<dir>` 的 `mount.lock`/`lease` 也属这一信任面。

## 真实挂载测试的工具路径绑定（测试侧）

- `tests/secure/real-tool-path.ts` 在每个 Vitest 文件实例内保存不可变的 gocryptfs 元数据快照（显式 parent PATH，忽略空项、拒绝相对目录；不执行工具）。真实 capability 与 fixture 共用该快照；机器原本缺依赖仍按原门跳过，已 capable 后绑定失效、权限改变或 bridge 创建失败必须 fail，不能变成 skip 或重新选工具。
- 共用 `RealHarness`（可显式注入 binding）和 fuse / off-golden real / N1 / N2 的局部 fixture 各在 owned、物理、0700 scratch 下新建独立 `real-tools/`，只允许 `gocryptfs` 一个 symlink，指向选中的绝对 realpath。它与可写假脚本的 `bin/` 分离，避免覆盖 fake 时沿链接写坏真实 binary；冲突、断链、非 owner/权限异常不覆盖、不修复、不清理其它目录。
- 默认子 PATH 仅为 fake bin → node-only bin（如单列）→ real-tools → `/usr/bin:/bin`，绝不携带整个 parent `.local/bin`、nvm 或 `/usr/local/bin`。初建时做文件系统级 gocryptfs/fake-pi 可达性检查；真实 direct init/mount（含 convert 内层 cipher、N1 额外 cipher、N2 独立 init fixture）显式使用同一 binding 或受控 env。`tty` / `plain` / spawn 不重建 bridge、不重新 resolve；显式完整 PATH override 完全由调用方控制。
- fake 模式不建 bridge；fake pi 始终优先，fake sync `-f`、fake fusermount 和 missing-getfattr 注入不补真实工具。bridge 白名单不含 sync/getfattr/node/pi；普通 execvp 对非可执行候选仍可能继续查尾部，路径绑定不承诺 inode 级可信执行（快照后的同路径文件替换仍有 TOCTOU）。
- `real-tool-path.test.ts` 是无挂载 Tier 2 proc 测试，仅执行自有 marker（包括 RealHarness 注入 binding 的 init 参数模拟），验证 A 快照后 parent 换 B、direct/child 仍 A、B 零调用，以及隔离/错误/并发策略。隔离 PATH 缺 getfattr 只证明不补回 parent，**不代表产品 69**；产品 69 静态复用 `convert-preflight.test.ts` 的既有 ports/context 用例（missing getfattr、错误文本、锁/flow 前零副作用）。该文件 import 会扫描真实 `/proc`，受限无挂载验收不运行它；既有 harness ownership 测试的 cleanup 也会遍历 `/proc`，同样不满足仅 self/自建进程访问的验收边界。此门不证明真实 FUSE、密码、namespace 或实际挂载生命周期通过；真实验证仍需另获授权并走正式 secure 预检/锁，不改 timeout、XC2 或 golden。

## 旧版本楔死保险库的恢复（人工，无自动化脚本）

症状：旧版本以词法拼写挂上的挂载，升级后仍读作 `foreign`（全局明文挂载残留、`mount.lease` 被占 ⇒ unlock/run/lock/export 卡死）。

1. **精确查询**：`findmnt -J -o TARGET,FSTYPE,SOURCE --mountpoint <mnt>`。`<mnt>` 取 `pi-secure status` 打印的路径（祖先链规则保证它是物理路径）；`--mountpoint` 精确匹配，JSON 无八进制转义；多条记录时以最后一条为准。不要 `grep <mnt> /proc/self/mountinfo`（子串、正则元字符、`\040` 转义都会误判）。
2. **人工确认归属**：查询结果「**可能**与本库 cipher 的另一种拼写一致，**无法据此证明归属**，需人工确认」。须全部满足：
   1. 最后一条 FSTYPE 为 `fuse.gocryptfs`；
   2. `realpath <SOURCE>` 等于 `realpath <dir>` 加 `/cipher`，且二者 `stat -c %d:%i` 相同（这只说明此刻路径相同，不证明 daemon 当初打开的是它）；
   3. `pgrep -u "$(id -u)" -a gocryptfs` 中有进程，其命令行带该 SOURCE 与 `<mnt>`，且 `ls -l /proc/<pid>/fd` 含 `<dir>/mount.lease`；
   4. `pi-secure status <n>` 无 private 实例块（若有，走 private 的 lock 流程）；
   5. 你确认没有其他会话或他人有意挂载它。
3. **卸载**：先用 `fuser -vm <mnt>` 关闭占用者，再 `fusermount3 -u <mnt>`。`-uz`（lazy detach）只摘除路径：已打开的文件或 cwd 在关闭前仍可读写明文，daemon 与租约会活到最后一个引用释放（期间 unlock 可能报 76）——**不等价于已锁定**，只作最后手段。
4. **收尾核对**：`findmnt` 查无记录，且 `flock -n <dir>/mount.lease true` 成功，再 `pi-secure unlock`。

## 设置文件协议（#54）

设置文件改名 `pi-subagent.json` → `pi-toolkit.json` 并跟随 agentDir（设计：`docs/dev/settings-rename/plan.md` r3）。secure 侧的四条不变式：

- **锁名固定**：`<设置目录>/.pi-subagent.json.lock` 永不随文件名变——新旧插件、新旧 launcher 必须争同一把锁（I7 例外项）。
- **launcher 按 agentDir 解析、新名优先**：helper.mjs 镜像 `resolveAgentDir` + `resolveSettingsLocation`（含 `~/.pi/agent` 继承回退）；两个名字都没有时 launcher 仍默认旧名（拍板②）。launcher 只补完崩溃遗留的迁移中间态（`healSettingsFileLocked`），不发起迁移。pi 与 launcher 必须在同一套环境变量下运行；`status` 在非默认 scope 时打印 `[agentDir: env]` / `[inherited]` 后缀。
- **S6b fail-closed**：新旧两份文件同时存在且 `secure` 段不一致时，domain 置 `secure:invalid`，launcher `run`/`unlock` 以 78 退出——宁可报错也不静默只用一份。
- **agentDir-in-vault fail-closed**：`PI_CODING_AGENT_DIR` 与任一已登记保险库的 `dir`/`mnt` 相互嵌套 ⇒ domain 判 locked、`status` 打印 `!` 行、`run`/`unlock`/`init` 退出码 78（登记表不能藏进它自己描述的保险库）。

另：`/secure status` 探测 PATH 上过旧的 pi-secure（realpath 后在它的 helper.mjs 里找新名标记），旧版且已迁移时给出改指本检出的 `ln -sf` 命令；pi-secure 与插件同版发布，安装链接必须指向同一检出。
