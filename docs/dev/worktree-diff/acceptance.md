# web-hub「worktree 文件 diff 查看」· 真机验收清单（worktree-diff plan v3 §6）

对应施工方案：`docs/dev/worktree-diff/plan.md`（v3 + §9.3 修订）。每条给出**操作 → 预期 → 取证方式**；
W 编号与 plan §6 一致。通用前置：

- 本机 `pi`（装了 pi-toolkit 且 `webHub.enabled`、`webHub.preview` 非 off）+ 一个浏览器 + 一部手机（W4/W12 需要 LAN）。
- 验收仓库建议用本仓库（pi-toolkit）或任意有真实改动的仓库；需要构造性场景（W5/W8/W9/W11/W13）用一个临时仓库。
- hub 日志：`~/.pi/agent/web-hub/logs/hub.log`（`wtdiff` 审计行、`wtdiff.git_failed` / `wtdiff.attr_changed` 告警都在这里）。
- 集成测试（`tests/integration/web-hub-worktree-diff.test.ts`）已覆盖服务端语义；本清单验的是**真机上端到端的人感**（UI 行为、键盘、手机、时序横幅），两者互补。

## W1 入口与清单一致性

| 项   | 内容                                                                                                                                                                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 在仓库里制造若干改动（修改 1 个文件、新增 1 个未跟踪文件、删除 1 个已跟踪文件），打开 web UI 的 agent 详情页 → WorktreePanel。                                                                                                                                  |
| 预期 | 有改动的 worktree 行的 dirty token 渲染为 `*N` **按钮**（非纯文本），带 aria-expanded；点击展开文件清单。                                                                                                                                                       |
| 取证 | ① 终端 `git status --porcelain --untracked-files=all` 的条数 = `*N`（受保护项与子模块除外——`*N` 来自 agent 采样，可能略多，由面板脚注解释，plan §2.8）；② 展开清单条数与 `git diff-index --numstat HEAD` 行数一致；③ 清单条目的 `+a −d` 与 numstat 对应行一致。 |

## W2 分屏视图

| 项   | 内容                                                                                                                                                                                         |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 展开清单 → 点击一个**多 hunk** 的修改文件打开对话框。                                                                                                                                        |
| 预期 | 默认分屏：左旧右新、双栏行号、删除行红底、新增行绿底、`@@` hunk 头分隔；同一 hunk 内删除行与新增行**段内配对**（逐行对照），数量不等的一侧以空位补齐；长行换行后两侧保持同一行高（不串行）。 |
| 取证 | 与 mockup（plan §4 配图）肉眼比对；换行验证用一条 >200 字符的长行（改前改后都存在）确认两侧不错位。                                                                                          |

| 项   | 内容                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- |

## W5 文件类型全覆盖

| 项   | 内容                                                                                                                                                                                                                                                                                      |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 临时仓库逐一构造并打开：① 嵌套目录里的新文件（`a/b/c/new.txt`，未跟踪）；② 已跟踪文件删除；③ 暂存重命名（`git mv` 后 `git add -A`）；④ 二进制（含 NUL 字节）修改；⑤ 仅 chmod（`chmod +x` 一个已跟踪文件）；⑥ 冲突状态（merge 留下 UU）。                                                  |
| 预期 | ① 显示合成的 new-file patch（全绿 `+` 行）+ 「未跟踪文件」横幅；② 删除视图全红；③ 重命名条目 `R` 徽标 + `orig → path` 标题，纯改名无内容差异时显示 rename-only 横幅（100% 相似）；④ 「二进制文件」提示态（无 patch 体）；⑤ mode-only 横幅；⑥ `U` 条目可展开（合并冲突按普通 diff 显示）。 |
| 取证 | 每类一张截图；`kind` 值可从 devtools Network 里 `/api/worktree-diff/file` 响应核对（`patch` / `binary` / `empty`）。                                                                                                                                                                      |

## W6 linked worktree 与非成员目录

| 项   | 内容                                                                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | `git worktree add /tmp/pi-wt-accept` 造一个 linked worktree 并放一个改动；面板上该 worktree 行应可展开查看。devtools 里把任一请求的 `wt` 参数改成非成员目录（如 `/tmp` 或另一仓库的路径）重发。 |
| 预期 | `pi-agent-*`（或任意 linked）行正常查看；篡改请求 ⇒ `403 {"error":"E_WTDIFF_DENIED","reason":"not-worktree"}`。                                                                                 |
| 取证 | 面板操作截图 + devtools Network 的 403 响应体。                                                                                                                                                 |

## W7 准入（denylist）

| 项   | 内容                                                                                                                                                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 操作 | 仓库内修改 `.env`（或新建 `.env.local`）；打开该 worktree 的清单；再在 devtools 里直接请求 `/api/worktree-diff/file?...&path=.env`。                                                                         |
| 预期 | `.env` **不出现在清单**、`total` 不计入；清单脚注（受保护文件说明）常显；直接请求 ⇒ `403 {"error":"E_WTDIFF_DENIED","reason":"denylist"}`；hub 日志对应审计行**无路径原文**（只有 `wtTag`/`pathTag` HMAC）。 |
| 取证 | 清单截图 + 403 响应体 + `hub.log` 里 `audit":"wtdiff"` 行内容。                                                                                                                                              |

## W8 历史读取（#1 防线）

| 项   | 内容                                                                                                                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | devtools 把 `file` 请求的 `base` 改成更早提交的 OID（`git rev-parse HEAD~1`）重发；再把 `base` 改回当前 HEAD、`path` 改成一个**不在清单里**的文件（历史上有、现已删除的路径最佳）。                               |
| 预期 | 前者 `409 {"error":"E_STALE_CTX","reason":"base"}`；后者 `409 ... "reason":"entry"`。UI 正常流里无需手工触发——`useWorktreeDiff` 收到 409 会**自动重拉清单**后以新 base 重试恰好一次，仍失败则显示「不可查看」态。 |
| 取证 | 两个 409 响应体；UI 自动恢复的截图（改动后正常点开仍是当前内容）。                                                                                                                                                |

## W9 大文件与截断

| 项   | 内容                                                                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 生成一个 2 MB 文本（如 `yes ABCDEFGHIJ                                                                                                                           | head -c 2097152 > big.txt`）并修改后打开；再造一个 >16 MiB 的文本打开。 |
| 预期 | 2 MB：显示截断横幅（patch 在 512 KiB 上限处截断、行边界裁剪），浏览器不卡顿；>16 MiB（超过 `core.bigFileThreshold=16m`）：git 报 binary ⇒ 「二进制文件」提示态。 |
| 取证 | 截断横幅截图 + Network 响应的 `truncated:true`；大文件显示 binary 提示。                                                                                         |

## W10 刷新与 staleness 横幅

| 项   | 内容                                                                                                                                                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 操作 | ① 对话框开着，agent 侧（终端）修改该文件并保存；② 点对话框内刷新；③ 把改动 `git commit` 后点刷新；④ 对话框开着，agent 提交导致 HEAD 前移，关闭对话框后再次点击同一文件。                                     |
| 预期 | ① 出现「工作区已变化」横幅（**不**自动重拉，D13）；② 刷新后横幅消失、内容为新版本；③ 「已无变更」（409 entry ⇒ 不可查看/清单态）；④ HEAD 前移后 `*N` 签名变化触发自动重拉清单，点击后正常显示（base 换新）。 |
| 取证 | ① ② ③ ④ 各阶段截图；devtools 里能看到④触发的第二次 `/files` 请求。                                                                                                                                           |

## W11 LFS / filter 驱动

| 项   | 内容                                                                                                                                                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 操作 | 在装有 git-lfs 的仓库：`.gitattributes` 绑定 `*.bin filter=lfs` 并提交一个 LFS 文件，修改它后打开清单。验证 git 未被调用执行 filter：hub 无法注入 `GIT_TRACE`（最小 env 剥离），改用 `strace -f -e execve -p <hub-pid>` 抽查。 |
| 预期 | 该条目标记「由 Git 过滤器管理」且**不可点击**（`filtered`，hub 侧 check-attr 标记）；`strace` 抽查窗口内无 `git-lfs`/filter 命令进程被 hub 拉起。                                                                              |
| 取证 | 清单条目禁用态截图；条目 tooltip 文案；strace 输出（或无 lfs 环境下以集成测试 T5 为准并注明）。                                                                                                                                |

## W13 版本与路径

| 项   | 内容                                                                                                                                                                               |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 本机确认 `git --version` ≥ 支持 `--attr-source`（2.45+；本方案按 2.53 实测）与 `which git` 在 `/usr/bin` 或 `/bin`。再在 PATH 外装一个 git（如 nix）并以该环境启动 hub，展开清单。 |

## 发布前（驱动执行与 index 卫生）

| 项   | 内容                                                                                                                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作 | 临时仓库配置 `filter.x.clean` 与 `diff.external` 指向 `touch /tmp/wtd-ran` 的脚本、`.gitattributes` 绑定后，经 web UI 打开该文件的 diff；记录 `.git/index` 的 `mtime/size/ino` 于打开前后。              |
| 预期 | `/tmp/wtd-ran` **不存在**（三层中和：L1 空树属性源 + L2 无条件置空 + `--no-textconv --no-ext-diff` + `hooksPath=/dev/null`）；`.git/index` mtime 不变（plumbing `diff-index` + `--no-optional-locks`）。 |
