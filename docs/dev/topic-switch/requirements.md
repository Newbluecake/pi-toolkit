# 新任务相关性识别 → 建议切换新会话（topic-switch）— 需求

> 2026-10-09 用户需求，主会话澄清结论。下游 agent 以本文为准。

## 目标

用户新请求到达时，若它与当前会话的历史对话**不相关**，且继续在当前会话处理**很贵**，就让用户确认是否
切到一个**干净的新会话**继续处理这条请求（原请求 + 附带图片原样带过去）。

## 已拍板的决策（用户）

1. **触发前提（经济门槛，用户原话）**：「前提条件应该是 cache 已过期，然后是上下文比较长，比如单次请求的成本
   超过 $0.5 的情况下」——即：
   - 当前会话的 prompt cache **已过期**（下一次请求会把整段前缀按 cache-write / 全价重新计费）；
   - 且按当前模型价格估算的**下一次请求成本 > $0.5**（阈值可配置，默认 0.5 USD）。
   - 「上下文比较长」不再单独设 token 门槛，由上面的成本估算体现。
2. **切换内容**：**干净新会话**——只带用户这条新请求（含图片），不做交接、不带摘要。
3. **默认开启**（设置里可关）。
4. 判断方式：用户未单独选择（回答被上面的前提条件替代）。主会话按推荐暂定 **A：前提全部满足后，用便宜模型做
   相关性判断**（短超时，超时/出错一律放行）；architect 可提出更优方案但需说明理由。

## 主会话补充的过滤条件（零成本，先于经济门槛/模型判断；architect 可调整）

- 只在主会话做；子 agent / consult 会话不做；功能开关开着；本会话不在「别再问」冷却期（用户拒绝过一次后本会话
  不再问，或直到上下文再显著增长）。
- 空闲时的新一轮请求才检查；流式期间的 steer / followUp 一律跳过。
- 本会话有运行中的子 agent / 后台 bash 任务时跳过（切走会丢下它们）。
- 跳过：`/` 命令、`//` 前缀、扩展内部触发的消息、过短消息（如「继续」「push」「方案二」「好的」）、明显承接上文的
  消息（指代词「这个/刚才/上面/继续…」，或上一条回复在提问 / 刚问过 ask_user）。
- 时间间隔可作为加分信号（距上次回复越久越像新任务）——但缓存过期本身已隐含「隔了一段时间」。

## 交互

- 终端（TUI）与 web-hub 都要能确认（复用 ask_user 的双端竞速弹窗或等价机制，先答者生效）。
- 选项：切到新会话并继续 / 留在当前会话（并进入本会话冷却）。
- 用户选「留在当前会话」或弹窗超时/取消 ⇒ 原请求在当前会话照常处理，绝不丢消息。

## 不变式

- 任何失败（估算缺数据、模型调用超时/报错、UI 不可用、无法新建会话）都 **fail-open**：原请求照常进当前会话。
- 绝不吞消息：被拦截的请求要么进入新会话，要么回到当前会话。
- 不在 print 模式 / RPC 无 UI 时弹窗（直接放行）。
- 计时器一律 unref；无模块级可变状态（`/reload` 重激活规则）。
