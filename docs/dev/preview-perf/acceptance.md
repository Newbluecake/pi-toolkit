# web-hub 预览性能 · 真机验收清单（P4，preview-perf）

> 配套：`plan.md`（r3）§6.4、`PB-report.md`（§3 改动前基线 / §7 P3 复测 / §8 P4 门槛与虚拟基线）。
> 本文是**人工终裁**清单：用户在真实 web-hub 浏览器里逐条勾选；探针（`npm run probe:preview-perf`，不进 CI）
> 已覆盖 headless 数字与功能断言，这里补的是手感、读屏、触屏与真机帧感。每条给操作步骤与预期现象；
> 不满足预期即勾「✗」并在备注里写现象（回滚/降级出口见 plan §8.3）。

## 0. 环境准备

1. `pi install` 装好本包（不要只靠父进程 `-e`），`webHub.enabled:true`；`timeout 600 npm run build:web` 后
   `/reload` → `/webhub restart` → `/webhub open`；旧标签页刷新到新 UI。
2. DevTools Network（禁缓存）与 Console 全程开着；任何 console.error / CSP 违规即失败。
3. 语料：`node tests/fixtures/preview-perf/gen-corpus.mjs --out /tmp/pp-corpus`（或手动）准备——
   实际上真机直接用真实文件即可，推荐组合：
   - `src/stack.ts`（3609 行，170 KB，>600 行 ⇒ 虚拟体，>100 KiB ⇒ 只有 Worker 高亮能着色）；
   - 任一 ≤200 行 / ≤8 KiB 的小源文件（首帧即高亮档）；
   - 600 行上下各一份（虚拟阈值两侧：≤600 行全量 NumberedCode，>600 行虚拟）；
   - 一行超长的文件（如拼接出 4 KB+ 单行；或用 `tests/fixtures/preview-perf/longline.js` 的思路合成）；
   - 一份持续追加的日志（`tail -f` 到文件 / 重复 `echo >>`）。
4. 行号默认开（`pwh_linenumbers`）；字号缩放用 UI 设置的 80%/100%/300% 三档。
5. 手机带：`webHub.lan` 开启 + `/webhub passwd`，手机访问 LAN URL（<768px 布局）。

## A. 大文件打开 / 滚动 / 拖动 / 缩放手感（Chromium 主测）

- [ ] **A1 打开**：点击 transcript 里的 `src/stack.ts` 路径开预览窗。预期：明显「秒开」（探针 warm ~52 ms），
      首帧是纯文本行，高亮在打开后很快到达（Worker，见 C3）；DevTools Performance 录制一次打开，
      主线程没有 >50 ms 的长任务块。
- [ ] **A2 滚动**：滚轮 / 触控板连续滚动 + 快速甩动到中部再到底。预期：行内容跟随无肉眼撕裂；
      只在滚过块边界时加载行（DevTools Performance 里滚动帧的主线程工作很小，探针 ~1.3 ms/步）。
      甩动时允许露出一帧底色（K3 残留），稳定后不应白屏。
- [ ] **A3 拖动**：按住标题栏拖动窗口。预期：整窗跟手，正文不闪不重排（P0 非继承几何变量）。
- [ ] **A4 八向缩放**：逐个拖 8 个把手，特别是横向 `e` 与 `se`。预期：大文件下不再有 r0 时代的
      整体重排卡顿（探针 resize.e 21.5 → 0.7 ms/步）；虚拟体不换行（K4：横向滚动看长行，已拍板接受）。
- [ ] **A5 300% 字号**：字号切到 300%，重复 A1/A2。预期：滚动位置按逻辑行保持（锚点重定位）；
      滚到底能看到最后一行（行数上限 50 万内）或看到「已超过本视图上限」提示行。
- [ ] **A6 远跳**：拖滚动条从顶直接到底、再回顶。预期：单次跳动可感知但不清屏假死（探针远跳
      10–13 ms；帧感以真机为准——此项探针未设闸，见 PB-report §8.2）。

## B. 窗口内查找（Ctrl/⌘+F）

- [ ] **B1 拦截与两次规则**：焦点在预览窗口正文内按 Ctrl+F（Mac ⌘F）→ 打开窗内查找栏并聚焦输入框；
      **再按一次 Ctrl+F**（此刻焦点已在查找输入框里）→ 放行给浏览器**页面查找**（浏览器自己的查找条出现），
      且页面查找只能命中当前可见的行（常驻说明里写了这一点）。
- [ ] **B2 Esc**：查找框内按 Esc → 只关查找栏、预览窗**不**关（不触发 PreviewHost 的 Esc 关窗），焦点回正文。
- [ ] **B3 上下项**：输入一个多次出现的词，Enter/Shift+Enter（或 F3/Shift+F3、Ctrl+G/Ctrl+Shift+G）逐项跳转，
      当前项高亮更醒目并滚动到视口中部；计数显示 `cur / n`。
- [ ] **B4 计数与旁注**：构造 >10000 次命中（如单字母）→ 计数显示 `10000+`；把命中词放进超长行的截断区
      （>4096 码元之后）→ 命中计数存在但标记只到截断点，旁注提示「超出显示部分」、建议完整视图。
- [ ] **B5 大小写**：Aa 开关切换 `İ`/`Σ` 等大小写行为与说明一致（保持长度的逐码点折叠）。
- [ ] **B6 两窗独立**：开两个大文件窗口各自查找，关闭其一 → 另一窗的命中高亮不受影响。

## C. 高亮路径

- [ ] **C1 ≤200 行首帧即高亮**：打开一份 ≤200 行 / ≤8 KiB 的小源文件。预期：**首帧就是带色 token**
      （无「先黑白后上色」闪烁）。
- [ ] **C2 更大文件先纯文本后高亮**：打开 200–600 行的文件（NumberedCode 路径）→ 首帧纯文本，
      高亮约 150 ms 后到达换上色（P5 尺寸闸门的取舍，无长任务卡顿感）。
- [ ] **C3 Worker 高亮 stack.ts**：打开 `src/stack.ts`（>100 KiB，主线程闸门必拒）。预期：**仍然上色**
      （Worker 放宽闸门 256 KiB/80k token），打开到上色期间页面可交互、无 >50 ms 长任务；
      Network 里可见懒加载的 `highlight-worker-*.js` 与 Worker 侧 `highlight-impl-*.js`，主线程不再拉 Prism。
- [ ] **C4 回落（可选）**：DevTools → 对 worker 脚本请求 Block（或离线）后重开一个大文件 →
      粘滞回落原闸门 ⇒ stack.ts 保持纯文本、600 行内文件仍主线程上色；取消 Block 后新开窗口恢复 Worker。

## D. 选区 / 复制 / 超长行

- [ ] **D1 拖选**：在 stack.ts 里拖选约 500–1000 行（含边缘自动滚动与反向拖选）→ 复制粘贴比对，
      等于所见的连续行文本。
- [ ] **D2 Ctrl+A 逻辑全选**：焦点在虚拟体内 Ctrl/⌘+A → 全文背景选中提示「已选中全部 N 行」；
      先滚动、再复制 → 粘贴得到**已加载全文**（不是只有挂载行）；虚拟体内单击/按 Esc 取消全选。
- [ ] **D3 2048 上限**：拖选超过 2048 行（可借助 Ctrl+End 再 Shift 拖）→ 出现「选区超过 2048 行，无法保持」
      类提示；此后按 Ctrl+A / 完整视图复制作为替代。
- [ ] **D4 超长行截断标记**：打开含 4 KB+ 单行的文件 → 行尾出现灰色 `…(+N)` 样式标记（CSS 生成内容）；
      选中该行复制 → **只有屏显前缀**（已拍板 ②），标记文字 `…(+` 不进剪贴板；
      头部「复制」按钮/Ctrl+A 复制得到完整行；`path:行号` 一行可用完整视图看全。
- [ ] **D5 截断行布局**：截断行与其上下行都是单行高（标记不掉行、不叠字）。

## E. 完整视图 / 行号关 / 流式 / 多窗口

- [ ] **E1 完整视图切换**：大文件窗口头部「完整视图」按钮（`aria-pressed`）→ 切成单文本 DOM：
      可 Ctrl+F 用**浏览器原生查找**搜全文、可原生拖选复制全文；再点一次回虚拟体；只影响本窗口。
- [ ] **E2 读屏提示**：虚拟体被读屏聚焦时能听到 sr-only 说明（按需完整视图/文件内查找/复制全部）——
      详细读屏步骤见 G。
- [ ] **E3 行号关闭路径不变**：设置里关行号（`pwh_linenumbers=0`）重开文件 → 单 `<pre>` 全文 DOM、无 gutter，
      与 preview-perf 之前的行为一致（r0 legacy 分支）；重开行号恢复。
- [ ] **E4 流式日志**：打开持续追加的日志文件 → 分段加载推进、行号跨段连续、滚动到底跟随（IO 哨兵），
      状态行（加载中/已到 cap/文件变更）照常；流式期间不高亮（契约）。
- [ ] **E5 六窗口**：同时开 6 个不同大文件预览窗，级联点击轮流激活 → 每次点击无明显卡顿（探针 0.01 ms/点击），
      旧窗口内容保持不重置；全部关闭无泄漏（Console 干净）。

## F. 手机 <768px

- [ ] **F1 打开与滚动**：手机 LAN 打开 stack.ts → 全屏栈式预览，打开快（探针 390×844 ~64 ms），
      触屏滚动/惯性顺畅，露底可接受。
- [ ] **F2 触屏选择**：长按出选择手柄，拖选一段复制成功（不保证 >2048 行跨块选区，同 D3）。
- [ ] **F3 查找与完整视图**：B1/E1 在触屏上的入口可用（查找栏按钮/菜单内路径），Esc 规则不适用触屏。
- [ ] **F4 iOS Safari（有设备时，plan §6.4）**：iPhone/iPad 上打开大源文件——触屏长按出选择手柄后拖选一段并复制；快速惯性滚动时观察是否露底（允许一帧底色，稳定后不应白屏/错位）。无设备则登记「未测」。

## G. 读屏（Orca + Firefox，必做）

1. 环境：`orca` 已装（`sudo apt install orca`）；Firefox 打开 web-hub（loopback 或 LAN 均可）。
2. 开一份 >600 行的源文件预览窗，Tab 聚焦到预览正文 → 预期**先听到 sr-only 说明**
   （大文件按需渲染，读屏只能读到可见部分；完整视图可连续阅读；Ctrl+F 文件内查找；Ctrl+A 复制全部）。
3. 在窗内继续 Tab / 用读屏遍历 → 能找到「完整视图」按钮，激活听名字与状态（aria-pressed）。
4. 开完整视图 → 从光标处连续朗读，能一路读到文件**末尾**（不再只是可见窗口）；记录朗读是否流畅、
   在中途追加内容（流式文件）时是否被打断。
5. 回虚拟体，逐行听行号 `::before` 的朗读表现：记录行号是否被读出（预期：Chromium/Firefox 系会读出，
   虚拟模式已带 `content: counter(pvline) / ""` 的空 alt——**读不出行号才算 alt 生效**，如实记录两种结果）。
6. 听超长行行尾 `…(+N)` 标记：`data-clip-label` 的「本行超长，已截断 N 个字符」是否被读出
   （不支持 alt 的引擎读 `…(+N)` 本身，同样如实记录）。
7. NVDA/Chromium、VoiceOver/Safari 有条件再做（已拍板 ⑤），结果登记在本节末尾。

读屏结论登记：Orca+Firefox = ☐通过/☐不通过（现象：________）；其余引擎 = ☐未测/☐通过/☐不通过。

## H. WebKit / 引擎补测

- 本机 headless 探针的 WebKit 一直 skip（缺系统库）；真机若用 GNOME Web/Epiphany 或需要 WebKit 面补测，
  先补依赖再跑探针：

  ```sh
  # 需要 sudo（安装 WebKit 运行库，如 libevent-2.1）
  npx -y -p playwright@1.63.0 playwright install-deps webkit
  npm run probe:preview-perf -- --virtual --gate   # 或 --quick
  ```

- WebKit 预期：功能断言全过（虚拟体、查找、选区、截断行），无 Long Tasks API（longtaskSupported:false，
  「观察不到不等于 0」，报告如实记录）；Custom Highlight 不支持时查找只标当前项（预期回落）。
