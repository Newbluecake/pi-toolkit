## 3. 总体设计

### 3.1 词汇

`MessageKind = "progress" | "report" | "directive" | "result" | "dead_letter"`；可发送的 kind（schema 顺序不变）为 `progress | report | directive`。凡是原来判断 `"finding"` 的分支，原样换成 `"report"`，语义与配额规则不变。设置键 `fabric.reportQuota`，默认 10。

### 3.2 I10 例外范围与不兼容面（用户已批准）

1. `message_agent` schema 中 kind anyOf 的第 2 个 const：`"finding"` → `"report"`（wake on/off 两种 schema）。
2. 持久化 `FabricRecord.kind`：新记录写 `"report"`；旧值不迁移，按 §3.3 处置。
3. context-message 正文首行 `[fabric <kind> …]`（`formatMessage`），随通用 `custom_message.content` 字符串上 wire（F2-b）：内容变为 `[fabric report …]`，字段和结构不变。
4. 设置键 `fabric.findingQuota` → `fabric.reportQuota`（设置面，不是 wire；列在这里是为了把不兼容面列全）。
5. fabric-off 下也可见的模型面文本：`steer_subagent` 的 description 与 `reply` 参数 description（F8），只做 §7.4 列出的词汇替换。

**不在例外内、必须保持不变**：hub PROTO 与 caps、`StatusInfo`、所有 `xs_*`/`thr_*` 帧、WireEntry 的字段集合、`subagent:fabric` customType 名、`FabricRecord` 其余字段、router 抛错原文 `message not authorized`（#33 已冻结其字节）、`message_agent` 的 `to`/`text`/`wake` 字段及 description、steer 的 `reply` 枚举（`none|ack|report`）与参数结构、所有 xs 枚举。AGENTS.md 的 I10 条文**不改**（`tests/docs/agents-md.test.ts` 钉了原文）；例外记录写进 `docs/dev/fabric-cross-session/README.md`（§4.5）和 commit 正文。

### 3.3 未知 kind 的处置（权威表）

「未知 kind」指 `!isMessageKind(kind)`，`"finding"` 是主要情形。总原则：**永不投递、永不注入 resume 提示词、永不发 dead letter、永不为它排定时器、不抛到宿主、不记正文**。

所有退役动作共用一个函数，新增文件 `src/fabric/unknown-kind.ts`（无状态，符合 I4）：

```ts
import { isMessageKind, type FabricRecord } from "../core/message.js";
import type { DeliveryEngine } from "../delivery/engine.js";
export const UNKNOWN_KIND_REASON = "unknown_kind";
/** #34: terminate ONE non-terminal record whose kind is not a current MessageKind. Idempotent, never throws, never
 *  retries, never issues a dead letter. Returns true iff this call moved it to `dropped`. */
export function retireUnknownKind(
  engine: DeliveryEngine<FabricRecord, FabricRecord["state"]>,
  record: Pick<FabricRecord, "key" | "kind" | "state">,
): boolean {
  if (isMessageKind(record.kind) || (record.state !== "pending" && record.state !== "claimed")) return false;
  return (
    engine.transition(record.key, ["pending", "claimed"], "dropped", { terminalReason: UNKNOWN_KIND_REASON }) !==
    undefined
  );
}
```

各入口的「排除」都使用同一个谓词 `isMessageKind`。
