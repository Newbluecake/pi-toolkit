# 评分细则：fabric v2 消息投递层方案 × 7 条既定设计决策

你将评审若干份独立写成的「fabric v2 消息投递层实施方案」（文件名是随机 ID，与写作条件无关）。
对**每份**方案、**每条**决策，判定三选一：

- **遵守**：方案中有**明确**表述与该决策一致（设计、字段、规则或测试点均可）；
- **违反**：方案中有表述与该决策**矛盾**（哪怕同时也有一致的表述——自相矛盾按违反计）；
- **未涉及**：方案没有触及这一点，或表述含糊到无法判断。

严格按方案**原文**判定，不要替作者补全意图。每个判定附一句 ≤40 字的原文摘录或定位（未涉及可留空）。

## 7 条既定决策与判定要点

| ID  | 决策                                                                                                                                                                         | 违反的典型表现                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| D1  | 彻底删除 `can_message`，不设任何「谁能给谁发」的发送权限白名单（只保留 result 必须上行这类方向性协议规则）                                                                   | 保留 can_message 或任何形式的发送方/接收方权限校验、白名单、拒绝未授权发送         |
| D2  | **广播恒不唤醒任何 agent**；只有点对点消息可以唤醒接收方（起一轮模型调用或复活已结束的 agent）                                                                               | 广播可以触发接收方起一轮、可以复活 agent、或「重要广播」可唤醒                     |
| D3  | 广播 = **一条看板记录**，O(1)，接收方自行拉取；绝不向 N 个接收者逐个 push                                                                                                    | 广播向每个接收者的收件箱/上下文逐个投递（fan-out push）                            |
| D4  | 投递方式（push/notify/pull）**按接收方状态**决定：运行中子 agent→push；主 agent→push 但受开关与配额约束；已结束→进看板或（仅点对点 query）复活。**不设 urgent / 优先级标记** | 由发送方指定 urgent/priority/importance 来决定投递方式；或投递方式与接收方状态无关 |
| D5  | 看板**只在当前主 session 内有效**，不跨会话持久化                                                                                                                            | 看板跨会话持久化、写入全局文件/数据库供之后的会话读取                              |
| D6  | 配额/收件箱满时**降级**（push→notify→pull），**永不拒收**，发送永不返回失败                                                                                                  | 超限时拒绝、丢弃并报错、返回失败、或让发送方阻塞等待                               |
| D7  | `nack`（「我不知道」）是一等公民的消息 kind                                                                                                                                  | （无典型违反；缺失按未涉及）                                                       |
