## 1. 背景与目标

### 1.1 需求

- **R1（全连通）**：任意两个 agent 之间可点对点通信，也可一对多广播。
- **R2（发送永不阻塞）**：发送方绝不等待对方回复——`message_agent` 调用必须立即返回，投递、唤醒、resume 全部异步发生。

### 1.2 硬约束（来自仓库不变量，v2 不得破坏）

- 零悬挂：所有投递路径有上界（v1 已有 `fabricSteerTimeoutMs` race、TTL、maxAttempts）。
- I-F10 claim 单写者（select→claim→dispatch 同步段）；I-F11 死信义务是持久化字段的纯函数；I-F12 root context 有界；I-F13 ref 查重同段；I-F14 verdict 有限到达；I-F15 verdict 实例隔离（`src/fabric/mailbox.ts` / `router.ts`）。
- 三不变量：① finding/directive 至少投递一次或以带审计死信终结；② 一条原始消息至多一条死信；③ root LLM context 速率与总量有真实上界。
- 子会话对本扩展惰性（HOST_KEY guard）；ref'd timer 必须 `unref()`；无模块级可变状态（`/reload` 重建 stack）。
- 不可信输入横幅：一切跨 agent 注入文本带「不可信输入」警示（`formatMessage`）。
- UI 文案语言切分：紧凑行内标记只用英文 token。

### 1.3 v1 差距（相对 R1/R2）

| #   | v1 现状                                                                | 差距                                                      |
| --- | ---------------------------------------------------------------------- | --------------------------------------------------------- |
| G1  | 授权默认 `["parent"]`，跨树仅 `mention`（root 直属、progress/finding） | 深层嵌套 agent 之间无法点对点                             |
| G2  | 无广播                                                                 | 无一对多                                                  |
| G3  | `mention.send()` 在工具调用线程内 `await spawn`（resume 路径）         | 工具调用会被 spawn 准入拖住（R2 边缘违约）                |
| G4  | 收件箱背压只有 `rootInboxCap`（仅 root）                               | 非 root 目标可被灌满 context                              |
| G5  | 无共享公告区                                                           | 广播若按 fan-out 逐条 steer 会造成唤醒风暴与 context 膨胀 |

## 3. 总体设计

### 3.1 寻址模型（R1 的落点）

`message_agent.to` 的 v2 文法（**ToRef**）：

| 形态       | 解析为        | 授权要求                                                | 说明                       |
| ---------- | ------------- | ------------------------------------------------------- | -------------------------- |
| `<runId>`  | 节点（exact） | 树关系 ∈ can_message，**或** `any`                      | v1 原样 + `any` 放开跨树   |
| `root`     | 节点          | `parent`（默认即有）                                    | v1 原样                    |
| `@<label>` | registry 解析 | `mention`（root 直属，v1 原样）**或** `any`（任意深度） | `any` 下解除 root 直属限制 |
| `@fleet`   | 看板广播      | `broadcast`                                             | 一对多；落看板，不 fan-out |

解析失败/未授权一律结构化错误返回（见 §4.9），不 throw。runId 寻址的目标不存在（不是已知节点）→ `unknown_target`。

### 3.3 投递方式决策表（push / notify / pull 由什么决定）

**决定因素 = 目标状态× 目标身份× kind 的 channel 推导。**

| 目标           | 状态          | 生效 channel                                               | 方式                                                                                                           | 唤醒?            |
| -------------- | ------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------- |
| run            | running       | context（恒）                                              | **push**：steer 注入当前 run                                                                                   | 是（steer 语义） |
| run            | pending_start | context                                                    | **deferred push**：pump 挂起，`markRunning` 后投递；TTL 到期未启动 → finding/directive 死信 / progress abandon | 否（等待）       |
| run            | gone（终态）  | —                                                          | **不投递**：finding/directive → 死信回投发送方；progress → drop（例外：@label 显式 resume，见 W6）             | 否               |
| root           | 任意          | context                                                    | **notify**：`sendMessage(deliverAs:"steer", triggerTurn:true)`                                                 | 是               |
| root           | 任意          | display（仅 progress 且 progressChannel=display 且可渲染） | **display**：appendEntry 仅渲染                                                                                | 否               |
| 看板（@fleet） | —             | —                                                          | **pull**：看板存储 + root 非唤醒摘要（`triggerTurn:false`）+ `board` 工具拉取 + resume prompt 摘要             | **绝无**         |

一句话：**目标活着 → push（root 用 notify）；目标没起 → 等待或死信；目标没了 → 死信；看板永远 pull。**

### 3.4 接收方唤醒规则（W1–W7）

「唤醒」= 使目标产生一轮模型调用。fabric v2 中**仅有三条唤醒通路**：

- **W1（running run 的 push）**：steer 注入 → pi 续跑当前 run（v1 原样，唯一子 run 唤醒面）。
- **W2（root 的 notify）**：context 通道 → `triggerTurn:true` 唤醒空闲主循环（v1 原样）；display 通道永不唤醒（v1 原样）。
- **W6（显式复活）**：`@label` 指向**终态** run → 携带消息 resume（D-M4/D-M6 用户已拍板语义原样保留），消息文本（带不可信横幅）成为新 run 的 prompt；新 run 为 root 直属，label re-point。**v2 将其扩展为 `any` 授权也可 resume 任意深度 label**，复活仍受 spawn 准入（concurrencyLimit / budget / resumeLocks）约束。除 W6 外**任何消息不复活已结束的 agent**（runId 寻址到 gone → 死信，不 spawn）。

非唤醒规则：

- **W4**：pending_start 目标挂起等待，不唤醒。
- **W5**：gone 目标不投递不复活；发送方异步收到死信（或 progress 静默 drop）。
- **W7**：**看板/广播绝不唤醒任何人**——root 在 turn_end 收非唤醒摘要（`triggerTurn:false`，照抄 quota hook 通道）；running agent 用 `board` 工具主动拉；被复活（W6）的 agent 在 resume prompt 末尾附看板摘要（拉取时机=复活）。
- **死信**：system→sender 的 `dead_letter` 记录走 mailbox 正常投递（sender 已 gone 则 `suppressed_sender_gone`，v1 原样）。

### 3.5 看板（共享公告板）模型

- **存储**：stack 内存环形窗口 + host 会话文件自定义条目 `subagent:fabric:board`（仅 post 时 append，与 `subagent:fabric` 记录同款追加式持久化）。`/reload` 后从 prefetched 条目 hydrate，seq 从已见最大值续。
- **有效范围**：**当前 pi 会话的 fleet（本 stack 生命周期）**。跨 `/reload` 存续（会话条目 readBack）；**跨会话/跨进程不共享**（fleet 本身就是会话 scope，树每 session 重建；跨进程共享需要文件锁与无主清理，MVP 拒绝）。
- **条目**：`{ id, from, kind(progress|finding), text, topic?, replyTo?, postedAt, ttlMs }`；text 按 `fabric.maxChars` 截断（router 同款 keep-head/tail 算法）。
- **有界性**：内存窗口 ≤ `boardMaxEntries`（post 时逐出最旧）；TTL 懒过滤（list/digest 时判 `postedAt+ttlMs`，**不加定时器**）；每发送方 post 配额 `boardPostQuota`；磁盘 append-only（与会话文件同寿命，天然随会话归档）。
- **消费面**：① root turn_end 非唤醒摘要（每轮至多 1 块、至多 `boardDigestMaxEntries` 行、每行截断 ~120 chars——不变量③的看板侧上界）；② `board` 工具 `list`（默认最近 20 条，全文随行返回，因条目本身 ≤ maxChars）；③ resume prompt 摘要（W6）。
- **广播无死信义务**：看板条目不是 FabricRecord，I-F11 义务函数不适用；post 的原子性 = admission 成功即持久可见。

### 3.6 数据流（两个典型序列）

```
p2p 跨树（A 深层 → B 深层，A 有 can_message: any）：
  A: message_agent(to="run_B", kind="finding", text, topic)
   → address 解析（无 await）→ router.admit（授权 any 分支、配额、B 侧 inboxCap）
   → 返回 {status:"accepted", key}（A 立即继续，R2）
   → mailbox.pump：B running → steer 注入（W1 唤醒 B 续跑）
   → B gone → TTL/即时死信 → system→A 的 dead_letter（异步反馈）

广播（A → @fleet）：
  A: message_agent(to="@fleet", kind="finding", text, topic)
   → authorize（broadcast 分支）→ board.post（配额/环形/TTL）→ appendEntry 持久化
   → 返回 {status:"board_posted", id}
   → root 下一 turn_end：非唤醒摘要块；running 同伴：不感知，直到自己调 board list；
     被复活的同伴：resume prompt 自带摘要
```

## 4. 接口契约

> TypeScript 严格模式（`exactOptionalPropertyTypes`）：可选字段一律条件展开 `...(x === undefined ? {} : { x })`；相对导入带 `.js` 后缀。

### 4.1 `src/core/message.ts`（envelope 与授权）

```ts
export type CanMessage = "parent" | "child" | "ancestor" | "descendant" | "sibling"
  | "self" | "mention" | "any" | "broadcast";            // +any +broadcast

export type BoardEntryId = string & { readonly __boardEntryId: unique symbol };
export function makeBoardEntryId(seq: number): BoardEntryId;   // `board:<seq>`，seq ≥ 1
export function parseBoardEntryId(v: string): BoardEntryId | undefined;

export interface MessageEnvelope {                       // 新增两个可选字段，其余不动
  ...
  topic?: string;          // trim 后 1..64 字符；超出/为空 → admission 拒绝（结构化 invalid_topic）
  replyTo?: MessageKey | BoardEntryId;   // 仅关联审计/渲染，不做存在性校验
}

export type Route =
  | MentionRoute                                           // { kind:"mention"; label; target }（v1）
  | { kind: "any"; target: NodeRef; label?: string }       // any 授权直达；label 存在时供审计
  | { kind: "broadcast" };                                 // 仅 authorize 用，不产生 FabricRecord

// via.mode: "tree" | "mention" | "direct"（+direct；any 授权的直达消息 hops=[]，lca 仍记真实树 lca）

export function authorize(input: AuthorizationInput): boolean;
// v2 判定矩阵（在 v1 分支之后追加）：
//  route.kind === "broadcast"：
//    kind ∈ {progress, finding} ∧ canMessage 含 "broadcast" ∧ from !== "system"
//    （directive/result/dead_letter 一律 false）
//  route.kind === "any"：
//    kind ∈ {progress, finding} ∧ canMessage 含 "any" ∧ route.target !== from ∧ 目标为合法 NodeRef
//    （绕过 relation 检查；self 仍拒绝）
//  其余分支（tree/mention/dead_letter/result/directive）逐字节保持 v1 语义。
```

`formatMessage`：`via.mode === "direct"` 时 header 显示 `relation=any`（与 mention 同款处理）；横幅不变。

### 4.2 `src/fabric/address.ts`（新文件，寻址层，零 pi import）

```ts
export type ToRef = string;   // 工具入参原文

export type TargetResolution =
  | { kind: "node"; node: NodeRef; route?: Route }       // runId / "root"（无 route = 树关系授权路径，v1 语义）
  | { kind: "label"; label: string; target: RunId; route: Route }  // @label（mention 或 any 授权由调用方判定）
  | { kind: "board"; route: Route };                     // @fleet
  | { kind: "error"; status: "unknown_label" | "unknown_target" | "bad_address"; detail: string };

export interface AddressDeps {
  registry: Pick<MentionRegistry, "resolve">;
  tree: Pick<FabricTree, "targetState" | "relation">;    // relation 供 canMessage 关系判定
  canMessage: readonly CanMessage[];                     // effectiveCanMessage 之后
  from: NodeRef;
}
export function resolveToRef(to: ToRef, deps: AddressDeps): TargetResolution;
// 规则：
//  "@" 前缀："@fleet" → board；其余 registry.resolve，未命中 → unknown_label；
//    命中且 canMessage 含 "any" → label（任意深度）；仅含 "mention" 且 root 直属 → label；
//    仅含 "mention" 但非 root 直属 → error(unknown_target? no——) not_authorized 由 admit 判定，
//    此处返回 label + route 由 authorize 最终裁决（保持 D-M1「解析与授权分离、结构化错误在门层」）
//  "root" / 合法 runId：目标必须 tree.targetState ≠ 未知节点；runId 不在树上 → unknown_target
//  其他字符串 → bad_address
```

> 约定：**寻址/配额/背压失败 = 结构化返回**（模型可自纠）；**授权/协议违规 = throw**（沿用 v1 `admit` 的 throw 契约与既有测试基线，见 §4.9）。

### 4.3 `src/fabric/board.ts`（新文件，看板）

```ts
export interface BoardEntry {
  readonly id: BoardEntryId;
  readonly from: NodeRef;
  readonly kind: "progress" | "finding";
  readonly text: string; // 已截断至 maxChars
  readonly topic?: string;
  readonly replyTo?: MessageKey | BoardEntryId;
  readonly postedAt: Millis;
  readonly ttlMs: Millis;
}

export interface BoardConfig {
  maxEntries: number; // fabric.boardMaxEntries，默认 100
  ttlMs: Millis; // fabric.boardTtlMs，默认 3_600_000
  postQuota: number; // fabric.boardPostQuota（每发送方每 stack），默认 10
  maxChars: number; // 复用 fabric.maxChars
  digestWindowMs: Millis; // fabric.boardDigestWindowMs，默认 600_000（reload 后摘要回看窗）
  digestMaxEntries: number; // 常量 3（摘要行数上界，不变量③）
}

export interface BoardPorts {
  append(entry: BoardEntry): void;
} // stack 注入 pi.appendEntry
export interface FabricBoard {
  post(
    from: NodeRef,
    kind: "progress" | "finding",
    text: string,
    opts?: { topic?: string; replyTo?: MessageKey | BoardEntryId },
  ):
    | { ok: true; id: BoardEntryId }
    | { ok: false; status: "quota_exhausted"; used: number; quota: number }
    | { ok: false; status: "invalid_topic" };
  list(opts?: { since?: BoardEntryId; limit?: number }): BoardEntry[]; // TTL 懒过滤，默认最近 20
  digestSince(lastDigestAt: Millis): BoardEntry[]; // ≤ digestMaxEntries，供 turn_end 摘要与 resume 摘要
  hydrate(entries: readonly BoardEntry[]): void; // /reload；seq 续 max；重置 lastDigestAt 基线
  postsBy(from: NodeRef): number; // 配额计数（hydrate 重建）
  lastDigestAt(): Millis;
  noteDigest(at: Millis): void;
}
export function createFabricBoard(config: BoardConfig, ports: BoardPorts, now: () => number): FabricBoard;
```

### 4.5 `src/fabric/mailbox.ts` 与 `src/stack.ts` ports（增量，最小）

### 4.6 `src/fabric/mention.ts`（改造：R2 的关键落点）

```ts
// send() 拆为同步 submit + 宿主异步执行（新契约）：
export type MentionSubmitResult =
  | AdmissionResult
  | { ok: true; status: "queued_resume"; label: string }        // 取代 awaited "resumed"
  | { ok: false; status: "unknown_label" | "not_root_child" | "not_authorized"
      | "target_not_ready" | "resume_rejected"; label: string; detail?: string };

export interface MentionChannelDeps {   // deps 不变（router/registry/query/spawn/from/generation/canMessage）
  ...
  issueSystemNotice: (to: NodeRef, text: string) => void;       // [新] stack 注入：resume 异步失败回投
}
export function createMentionChannel(deps): {
  submit(label, kind: "progress" | "finding", text: string): MentionSubmitResult;  // 纯同步，无 await
  flushResumes(): void;   // 内部 fire-and-forget：执行排队中的 resume spawn（catch → issueSystemNotice）
};
// submit 流程（承接 D-M6 第 1–4 步，唯一变化）：
//  终态目标 → 入内存 resume 队列 → 返回 {status:"queued_resume"}；
//  flushResumes 由 submit 尾部 void 触发（不 await）：spawn 成功 → 无后续消息（新 run 即反馈面，
//  label 已 re-point）；spawn 失败 → issueSystemNotice(sender, 横幅化失败文本)（见 §4.9 死信形态）。
//  resume prompt 末尾追加看板摘要块（board.digestSince(0) 前 digestMaxEntries 条，W6 拉取时机）。
```

`any` 授权的 @label 复活：label 深度不限（不走 root 直属校验），其余同 D-M6（横幅、label re-point、spawn 准入兜底）。仅 `mention` 授权时 root 直属校验保持（v1）。

| ------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 8. 兼容性

- **持久化兼容**：旧 `subagent:fabric` 记录无 topic/replyTo/via.mode 缺省兼容（mode 缺省视为 "tree"，v6 先例）；`subagent:fabric:board` 是全新 customType，老会话无此条目即空板。
- **行为兼容**：不配 `any`/`broadcast` 的部署，v2 行为与 v1 逐字节一致（唯一例外：mention resume 从同步 `resumed` 变 `queued_resume`——结果枚举变更，需同步更新 rpc/mention 相关断言与文档）。
- **设置兼容**：新键全部有默认值，旧 settings 文件无需迁移；`fabric.enabled` 总开关语义不变（默认 false，灰度）。
