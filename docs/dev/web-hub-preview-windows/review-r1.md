# 预览多窗方案评审 r1（gpt-6.1-sol，打回）

## 评审结论：打回

按 §11 的六个推荐项评审。主要问题是：目录链接路由违反已拍板范围；HTML capability 的保护与恢复论证不成立；多窗口模态语义与跨窗焦点循环互相冲突。以下问题需要先修订方案，再进入实施。

## 已核查项

- **状态机抽取可行性**：通读 `src/web-hub/ui/src/composables/usePreview.ts`。scope、probe 与单窗 seq/AbortController、tree、历史栈、分块控制器确实可拆分；没有发现必须改变主请求/分块流算法才能实现多窗的障碍。保留 `use-preview.test.ts` 作为单窗回归闸门成立，但不足以证明新 manager 的生命周期正确。
- **现有回归覆盖**：读取 `tests/web-hub/ui/use-preview.test.ts`，包括约 803–1098 行的分块测试，确认已覆盖 continuation 取消、迟到结果丢弃、E_SESSION_CHANGED、Retry-After、返回后的流恢复。读取 `preview-host.test.ts` 和 `preview-wiring.test.ts`，确认大量 host 用例直接使用单窗 handle。
- **probe 隔离**：读取 `usePreviewProbe.ts`，确认队列项携带 scope、结果按 scope key 入库，旧 scope 的迟到探测结果不会直接污染当前 scope；probe 应由 App 级拥有，不能随某个窗口关闭而销毁。
- **目录分类与路由**：读取 `MdInline.vue`、`PathText.vue`、`PreviewDirRows.vue` 和 `previewContext.ts`，确认 MdInline 传递 `dir:true`、PathText 共享 probe、目录钻取与文件行事件可以分别路由。
- **HTML cap 真实生命周期**：读取 `hub/preview/html-cap.ts`、`PreviewHtml.vue`、`PreviewText.vue`，核实 FIFO 驱逐、驱逐中止在途请求、切换源码导致 HTML 组件卸载、重新挂载重新铸造，以及 reload 按钮的显示条件。
- **CSP 首帧与更新路径**：读取已安装的 Vue 3.5.43 runtime。`runtime-core` 的 `mountElement` 在插入节点前通过 `hostPatchProp` 设置动态属性；`runtime-dom` 的 `patchProp → patchStyle → setStyle` 对对象中的 CSS 变量使用 `style.setProperty`，不是 `setAttribute("style")`。`main.ts` 使用 `createApp().mount()`，无 SSR/hydration 路径。方案选择对象形式 CSS 变量绑定有实际源码依据。
- **CSP 门禁范围**：读取 `hub/http.ts:193-199`、`csp-probe/Probe.vue`、`scripts/web-hub/csp-probe.ts` 和 `source-scan.test.ts`。确认现有 probe 覆盖初次挂载的对象 style 绑定，扫描禁止 rAF、HTML 注入和静态 style，下载实现有精确文件豁免。本次未重新运行 browser probe。
- **模态及其他浮层**：读取 `DirPicker.vue`、`SessionHistoryDialog.vue`、`PrivacyUnmarkDialog.vue`、`ProxyDialog.vue` 的 overlay 归属代码，确认单一 `.preview-overlay` 根保留了这些组件按包含关系判断事件归属的契约。读取 `ProxyPreview.vue`，确认它是独立的上层 overlay，不属于窗口内 Tab 循环。
- **附件预览样式**：读取 `AttachmentImagePreview.vue` 和 `preview.css`，确认它确实复用 `.preview-overlay/.preview-panel`。新增规则全部限定于 `.is-windows/.preview-window` 的方向正确，不能为多窗修改这两个基类的全局语义。
- **会话、隐私及路由关闭**：读取 `DashboardView.vue`、`usePrivacyLock.ts`、App 接线及 `logic/state.js`。隐私回锁调用根 `close()`，迁移为 closeAll 后可以复用。另方案 §3.4 对 list/detail 的描述不准确：当前 reducer 在 list 路由将 selected 置 null，scope watcher 应随之关闭，而非保持 selected 不变；应加入真实路由集成断言。

- **只读约束**：仅使用读取、搜索及 `git status --short` 等只读操作；未运行可能生成产物/缓存的构建或测试，未修改文件。工作区仍仅显示原有两个未跟踪方案目录。
