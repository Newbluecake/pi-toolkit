## 已核查项

- **准入链重走（重点 1）**：读 `src/web-hub/hub/preview/routes.ts` 全文。`handle()` 单入口 ⓪closing→①CSRF→②auth→③params→④限流+在途→⑤–⑦`openAdmittedPath`（open.ts 共享管线，denylist/虚拟根/`O_NOFOLLOW`/fstat 全在里面）→⑧`readSample`+`sniff`→⑨`readAndStream`。方案插入点（③参数解析、⑨传 `chunk`+`tracker`）与现状兼容，续读**结构上无法绕过**任何准入步骤；denylist/虚拟根对续读继续生效的结论成立。§6.1 R-walk 测试设计（spy 计 admitter 调用次数、denylist 命中即 403、symlink 替换拒绝、sessionId 变更 409）能真正钉住该属性。
- **offset/ident 校验（重点 1）**：`parsePreviewOffset` 规则（十进制/无前导零/safe int/<16 MiB）+ 五条 400 规则覆盖负数、非整数、超大、半截协议、互斥；`offset ≥ size` → 400 range。ident=sha256(`dev:ino:size:ctimeMs`) 前 128 bit：`Identity` 结构核对 `verify.ts:27-32` ✓；ident 是完整性令牌而非能力令牌（每次续读都重过准入；认证用户本就可读任意路径 U4），伪造/重放/跨文件复用均无安全收益，128 bit 截断不可逆，不泄露 size 以外信息（size 本来就在响应头里）。用 ctime 防 `utimes` 伪造的判断正确。
- **UTF-8 跨段（重点 3）**：读 `sniff.ts:240` `utf8SafeCut`——确认它在「全续字节垃圾数据」或「窗口仅 1 字节且为前导字节」时**确实返回 0**，方案的推进规则（`cut===0&&want>0⇒cut=want`）是必要且正确的；EOF 分支不截断 ✓；CRLF/孤立 `\r` 由 UI 分段器归一化+扣尾 `\r` 处理，与 `parseMarkdown` 的 `\r\n?→\n` 归一一致 ✓。
- **零卡死与限流（重点 2）**：读 `fs.ts` 全文——`racePreviewIo` tracker 可选、`previewFsStep` tracker 必选、`PREVIEW_FS_ZOMBIE_MAX=2` ✓；「stream.ts 读不计入 tracker」现状与方案「只有分段模式传 tracker」的只增改法兼容；桶 20/250ms、在途 2/8 常量核对 routes.ts:94-99 ✓；每段 ≤256 KiB body + ≤64 KiB 样本 + 可选 gzip，与首段同型 ✓；客户端 40 s（`PREVIEW_CLIENT_TIMEOUT_MS`，protocol/preview.ts:131）> ADMIT 8 s + STREAM.lan 30 s ✓。16 MiB 硬顶在 `parsePreviewOffset` 与 `want=min(...,ceiling−start)` 双层生效 ✓。
