# memory-jev · 项目记忆使用策略

**机制（自动打标、行内注释键位、守卫确认框）都在 `memory` 工具描述里，这里只讲策略：什么时候写、写什么、怎么对待回显。**

## 何时写

1. **先查后写**：写之前先 `memory view`（或 `search`）确认同一事实是否已存在。已存在且仍正确 ⇒ 不写；已过时 ⇒ `str_replace` 原地修正，不要 append 出重复条目；只有全新事实才新增。
2. **用户令当场写**：用户明确下命令、拍板、纠正行为时，立刻把这条令写进记忆（不等收尾）。用户令 = 用户说的话的忠实记录，不加自己的解读。
3. **经验收尾写**：自己踩的坑、排障结论、调研得到的项目事实，在任务收尾阶段写，不要每个小发现都打断去写。
4. **一次写一条完整事实**：条目 = 一个可独立成立的事实/规则（`- ` 开头的列表项）。带上下文（日期、实测来源、版本号），但不要把整个调试过程写进去。

## 行内权威注释（何时写）

语法与键位见工具描述。策略上：

- `<!-- mem user -->`：凡是转写用户原话/拍板的条目都加上——用户令标记着「用户权威」：工具不再拦截改写，用户本轮明确要求时直接改，否则先在回复里向用户提议，用户同意后再改。
- `<!-- mem lesson -->`：明确标注"这是我自己的经验（非用户指令）"时用；默认不用写。
- `expires=YYYY-MM-DD`：用户令/临时规则带明确期限时写（如"临时禁用到 10-21"）。到期后系统只提示，由用户确认后才删。
- `until="事件"`：条件型失效（如"直到 v0.9 发布"）。
- `private`：条目绝不能外发给分类器时写。
- 示例（一条完整条目）：

```md
- 发版前确认 GitHub CI 绿，红着发过事故（v0.8.1） <!-- mem user -->
```

## 写完之后

- **把回显转述给用户**：写入结果里的 `section:`/`jev:`/`similar:`/`conflict:` 行是给你的判断材料。看到 `looks like a user order` 而这条确实出自用户 ⇒ 补 `<!-- mem user -->`；看到 `looks temporary` ⇒ 补 `expires=` 或 `until=`；看到 `conflict:` ⇒ 按提示合并旧条目，或在回复里向用户提议改法（用户令只能提议）。
- `voided user rule:` 行说明你刚刚直接作废了一条用户令——必须在回复里向用户点明（改了什么、为什么）。

## 降级

- 回显 `jev: not tagged (partial: …)` 或 `(off: …)`：写入已成功，只是没打上派生标签。**这条条目此刻不会进入快速通道**；若它需要立即生效，给条目加 `<!-- mem tags=+标签名 -->` 手工标注，无需等待、也不要反复重写。
- 用户令改写已无确认框（2026-11 #26）：直接写入后主会话 TUI 会弹一条 warning 通知给用户，工具结果也带 `voided user rule:` 行——你仍要在回复里向用户转述这次作废；不确定该不该改时先提议、后动手。
- 旧记忆文件里的 `gate`/`gate=hold`/`nogate` 行内注释：解析兼容保留、无任何行为（gate 拦截功能 2026-11 已移除），新写入不要再加这些键。
