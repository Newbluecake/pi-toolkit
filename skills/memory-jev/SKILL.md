# memory-jev · 项目记忆使用策略

**机制（自动打标、行内注释键位、块格式与限额、守卫确认框）都在 `memory` 工具描述里，这里只讲策略：什么时候写、写什么、怎么对待回显。**

记忆是一个块一个文件：`<topic>.<seq>.md`，正文有字节上限，元数据（权威、状态、`rev`、到期、标签）在 frontmatter。工具只有 `view` / `create` / `update` / `delete` / `search`，**`update` 是整块替换且必须带 `rev`**。

## 何时写

1. **先查后写**：写之前先 `view`（或 `search`）确认同一事实是否已存在。已存在且仍正确 ⇒ 不写；已过时 ⇒ **原地整体重写**（`view` 拿 `rev` → `update`），绝不新增重复块；只有全新事实才 `create`。
2. **用户令当场写**：用户明确下命令、拍板、纠正行为时，立刻把这条令写进记忆（不等收尾）。用户令 = 用户说的话的忠实记录，不加自己的解读。
3. **经验收尾写**：自己踩的坑、排障结论、调研得到的项目事实，在任务收尾阶段写，不要每个小发现都打断去写。
4. **一个块 = 一条事实**：块不是笔记本，不要往里续写第二件事；相关但独立的结论拆成同 topic 递增编号的多个块。带上下文（日期、实测来源、版本号），但不要把整个调试过程写进去。
5. **改块前先 `view` 拿最新 `rev`**：缺 `rev` 会被拒（`E_REV_REQUIRED`）；`rev` 过期判 `E_CONFLICT` 并回显当前正文 ⇒ **合并后带新 `rev` 重试**，不要重试旧 `rev`。

## 权威与到期（何时标）

语法与键位见工具描述。策略上：

- **用户令标权威**：凡是转写用户原话/拍板的块都标 `authority: user`。这个标记意味着「用户权威」：工具不再拦截改写，用户本轮明确要求时可直接改，否则**先在回复里提议、用户同意再改**。
- **经验标经验**：明确属于自己推断/教训（非用户指令）时标 agent；默认不用刻意写。
- `expires=YYYY-MM-DD`：用户令/临时规则带明确期限时写（如"临时禁用到 10-21"）。到期后系统只提示，由用户确认后才删。
- `until="事件"`：条件型失效（如"直到 v0.9 发布"）。
- `private`：块绝不能外发给分类器时写。

## 写完之后

- **把回显转述给用户**：写入结果里的 `section:`/`jev:`/`similar:`/`conflict:` 行是给你的判断材料。看到 `looks like a user order` 而这条确实出自用户 ⇒ 补 `authority: user`；看到 `looks temporary` ⇒ 补 `expires=` 或 `until=`；看到 `conflict:` ⇒ 按提示合并，或在回复里向用户提议改法（用户令只能提议）。
- `voided user rule:` 行说明你刚刚直接作废了一条用户令——必须在回复里向用户点明（改了什么、为什么）。
- `delete` 是软删进 `blocks/.trash/`（`/mem restore --trash` 可找回），**不是**清理的默认手段：过时就 `update` 改写正文，只有整条事实彻底无效才删。

## 降级

- 回显 `jev: not tagged (partial: …)` 或 `(off: …)`：写入已成功，只是没打上派生标签。**这个块此刻不会进入快速通道**；若它需要立即生效，在 frontmatter 里手工标注 tags，无需等待、也不要反复重写。
- 用户令改写已无确认框（2026-11 #26）：直接写入后主会话 TUI 会弹 warning 通知，工具结果带 `voided user rule:` 行——你仍要在回复里转述这次作废；不确定该不该改时先提议、后动手。
- 历史块可能带着超出当前上限的字段（早期版本写的更长 `when` / `section`）：读取时按码点边界降级、**不改写文件**，`/mem doctor` 能看到具体字段与超出量。不要为了消诊断去手改用户的历史文件；要修就走 `update` 整块重写。
