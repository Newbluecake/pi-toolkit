# memory-jev · 项目记忆使用策略

**机制（自动打标、行内注释键位、块格式与限额、守卫确认框）都在 `memory` 工具描述里，这里只讲策略：什么时候写、写什么、怎么对待回显。**

## 两种布局，先认清楚在写哪种

同一份记忆可能处于两种布局，**工具表面不同，写错命令会直接报错**：

- **files / tiered（旧布局）**：一个主题一个 `.md`，条目靠 `- ` 行累积；`str_replace` / `insert` 原地改。
- **blocks（块布局）**：**一个文件 = 一个块**（`<topic>.<seq>.md`，正文有字节上限），元数据进 frontmatter（权威、状态、`rev`、到期）；工具只给 `view` / `create` / `update` / `delete` / `search`，**`update` 是整块替换且必须带 `rev`**，`str_replace` / `insert` / `rename` 会被拒绝并提示改法。

判断方法：`memory view`（不带参数）看是否给出 topic 表与块计数，或看目录下有没有 `blocks/`。不确定就先 `view`，不要凭印象选命令。布局切换（含迁移）属于运维动作，**不要为了写一条记忆去迁移目录**。

## 何时写

1. **先查后写**：写之前先 `memory view`（或 `search`）确认同一事实是否已存在。已存在且仍正确 ⇒ 不写；已过时 ⇒ **原地修正**（blocks：`view` 拿 `rev` 后 `update` 整块替换；files：`str_replace`），不要新增出重复条目；只有全新事实才 `create`。
2. **用户令当场写**：用户明确下命令、拍板、纠正行为时，立刻把这条令写进记忆（不等收尾）。用户令 = 用户说的话的忠实记录，不加自己的解读。
3. **经验收尾写**：自己踩的坑、排障结论、调研得到的项目事实，在任务收尾阶段写，不要每个小发现都打断去写。
4. **一次写一条完整事实**：条目 = 一个可独立成立的事实/规则。带上下文（日期、实测来源、版本号），但不要把整个调试过程写进去。块布局下这条尤其重要：**一个块就是一条事实**，不要把一个块当笔记本续写；相关但独立的结论分成多个块（同 topic 递增编号）。
5. **改块前先 `view` 拿最新 `rev`**：`update` 缺 `rev` 会被拒（`E_REV_REQUIRED`）；`rev` 过期会被判 `E_CONFLICT` 并回显当前正文 ⇒ 合并后带新 `rev` 重试，**不要重试同一个旧 `rev`**。冲突的另一半信息可以保留（`kind` 是建议身份），由你判断是否真的取代。

## 权威与到期（何时标）

语法与键位见工具描述。策略上：

- **用户令标权威**：凡是转写用户原话/拍板的条目都标 `user`（块布局是 frontmatter 的 `authority`，旧布局是行内 `<!-- mem user -->`）。用户令标记着「用户权威」：工具不再拦截改写，用户本轮明确要求时可直接改，否则**先在回复里提议、用户同意再改**。
- **经验标经验**：明确属于自己推断/教训（非用户指令）时标 agent/lesson；默认不用刻意写。
- `expires=YYYY-MM-DD`：用户令/临时规则带明确期限时写（如"临时禁用到 10-21"）。到期后系统只提示，由用户确认后才删。
- `until="事件"`：条件型失效（如"直到 v0.9 发布"）。
- `private`：条目绝不能外发给分类器时写。
- 示例（一条完整条目）：

```md
- 发版前确认 GitHub CI 绿，红着发过事故（v0.8.1） <!-- mem user -->
```

## 写完之后

- **把回显转述给用户**：写入结果里的 `section:`/`jev:`/`similar:`/`conflict:` 行是给你的判断材料。看到 `looks like a user order` 而这条确实出自用户 ⇒ 补权威标记（块布局改 frontmatter）；看到 `looks temporary` ⇒ 补 `expires=` 或 `until=`；看到 `conflict:` ⇒ 按提示合并，或在回复里向用户提议改法（用户令只能提议）。
- `voided user rule:` 行说明你刚刚直接作废了一条用户令——必须在回复里向用户点明（改了什么、为什么）。
- `delete` 是软删除（进 `blocks/.trash/`），**不是**清理的默认手段：过时了就 `update` 改正文，只有整条事实彻底无效才删。

## 降级

- 回显 `jev: not tagged (partial: …)` 或 `(off: …)`：写入已成功，只是没打上派生标签。**这条条目此刻不会进入快速通道**；若它需要立即生效，用行内标签手工标注（旧布局 `<!-- mem tags=+标签名 -->`；块布局写到 frontmatter 的 tags），无需等待、也不要反复重写。
- 用户令改写已无确认框（2026-11 #26）：直接写入后主会话 TUI 会弹一条 warning 通知给用户，工具结果也带 `voided user rule:` 行——你仍要在回复里向用户转述这次作废；不确定该不该改时先提议、后动手。
- 读历史文件时可能遇到旧格式的 `gate`/`gate=hold`/`nogate` 行内注释：解析兼容保留、**无任何行为**（gate 拦截功能 2026-11 已移除），新写入不要再加这些键。
- 历史条目可能带着超出当前上限的字段（早期版本写的更长 `when` / `section`）：读取时会按码点边界降级、**不会改写文件**，`/mem doctor` 能看到具体是哪个字段超了多少。不要为了消除这条诊断去手改用户的历史文件；要修就走 `update` 整块重写。
