# 模型路由细则（models.md）

SKILL.md 的「阶段→模型」表只给首选/回退；本文件给**能力画像**、闸门与失败处置。

> **本文件不写 provider，也不写完整 model id。** 具体「哪个 provider 现在挂着哪个模型、哪条线还有额度」
> 由 memory 注入（provider 表 / quota 行）给出；派单时按注入的完整 `provider/modelId` 原样传。本文件只回答
> 「这个阶段需要什么能力、哪个模型擅长这件事、谁必须与谁异源」。

## 能力画像

按**能力**选模型，不按厂商选。名字是能力档位的代号，不是可传的 id。

| 档位代号            | 擅长                                                                                                                          | 不擅长 / 注意                                                                 |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `opus` 档           | 架构设计、L3 方案制定、疑难 bug 定位、被打回两次的方案/开发；长上下文下的跨模块推理                                           | 贵；简单任务属于浪费（L0/L1 禁用）                                            |
| `sonnet` 档         | 通用开发主力：读代码准、改动收敛、遵循既有约定；UI 视觉细节与组件调试                                                         | 超大包（>1M 级上下文）通读吃力；评审深度不如专攻评审的 GPT 档                 |
| `kimi-k3` 档        | 前端开发首选；评审次选；订阅线便宜，256k 档更省；中文语境与长文档阅读                                                         | 超过 256k 上下文的大文件通读/大包验收/长会话续跑要换长上下文档                |
| `glm` 档            | 代码探索（便宜、1M 上下文、适合广撒网 grep/读文件）；开发实施；验收次选                                                       | 开发用了它的包，验收不得再派它（异源）                                        |
| `gpt-sol` 档        | 方案评审质量最好（与 Claude 系天然异源）；复杂方案攻坚；开发双首选之一（便宜、1M 上下文）；也可做验收（与 Claude/GLM 系异源） | 安全策略拒绝与传输错误要分开处置                                              |
| `deepseek-flash` 档 | 验收次选（与 Claude/GLM/Kimi 系异源、便宜、1M 上下文）；代码探索与 glm 并列                                                   | 做 verifier 有概率跑完核查不交结构化输出 ⇒ 出现即 resume 要求「直接提交结论」 |
| `fable` 档          | 受闸门保护的最后一档，仅 L3 疑难且 opus 档已明确失败                                                                          | **必须先 `ask_user` 批准**；成本约 opus 档 2.5 倍                             |

## 疑难升级阶梯（fable 闸门）

难度升级一律走这条阶梯，**不得跳级**：

```
sonnet 档 → opus 档（疑难默认天花板） → [ask_user 批准] → fable 档
```

- **opus 档是疑难问题的默认最高档**：架构设计、L3 方案制定、疑难 bug 定位、被打回两次的方案/开发任务，
  直接派 opus 档，不必请示。
- **fable 档受闸门保护**：只有 opus 档已经跑过并明确失败（方案被 reviewer 判 Blocker、或同一问题连续 2 轮
  无进展）时才考虑，且必须先 `ask_user` 拿到批准；问句写清「为什么 opus 档不够、fable 要解决的具体问题、
  预计成本」。用户未点头就继续用 opus 档迭代。用户主动点名 fable 视为已批准。
- fable 只用于 L3，常规任务禁止动用。

## 独立性规则（与 provider 无关，只看模型家族）

- **评审**：评审模型 ≠ 方案模型；首选评审专精档（gpt-sol 档 ⇄ kimi-k3 档），两者都与 Claude 系的方案/开发
  天然异源。kimi 开发的方案不派 kimi 评审。
- **验收**：验收模型 ≠ 开发模型，走回退链时跳过同系；异源即可；GPT 系已解禁，可按回退链参与验收。
  开发用了 glm 的包，验收不派 glm。
- **共享同一 provider 不等于异源**：异源看的是模型家族/训练来源，不是「换了条线路」。

## provider 与额度从哪来

- **provider 表**：由 memory 注入（哪个 provider 现在承载哪个模型、哪条是订阅线、哪条是按量线）。
  provider 下线/换线时改 memory，不改本文件。
- **额度**：系统注入的 `[quota]` 行。订阅额度窗口内不用就作废 ⇒ 有余量时优先用完订阅；只有 L3
  （≥90%）才跳过该 provider。额度行给出的替代只是**候选**：先判断是否胜任本阶段，胜任才优先用，
  不为用额度而硬凑。
- **别因「可用模型列表里没有」静默换模型**：列表可能只是 scoped 视图，注册表里仍在。按注入的完整
  `provider/modelId` 直接派；派发被拒再按回退链降级，并明说原因（2026-10-10 教训：看列表没有就换模型
  顶替，单日传输失败 4 次）。

## 失败处置：传输故障 vs 安全策略拒绝

- **传输层故障**（stream 中断 / 502 / 503 / 0 轮无进展超时 / 模型侧「no model progress」timed_out）：
  直接 `resume` **同一个 run** 换线续跑，不必请示、不重派新 run。429 换线。
- **中途换 provider 也一样用 `resume`**：run 一旦 abort 即 terminal 且 session 已持久化，
  `Agent({resume: <run_id>, model: <新 provider/id>})` 保留已有取证与轮次，只换后端。重派会从零重跑
  （2026-11-08 教训：把一次已跑 52 轮/36 分钟的验收作废）。例外：`isolation:"worktree"` 的 run 失败后
  不能 resume（worktree 已删）。
- **安全策略拒绝 ≠ 传输错误**（如 Anthropic「triggered restrictions on violative cyber content… Usage Policy」）：
  不自动按回退链重发原 prompt。先判定被拦内容：
  1. **误拦**（任务本身正当，如分析自家代码的签名/鉴权逻辑、协议兼容、错误处理）→ 可改派异厂商模型续跑，
     派单 prompt 写明正当目的与范围；
  2. 被拦部分**本身就是规避第三方风控/安全检测**（克隆客户端 TLS 指纹、伪造遥测/心跳流量、为躲检测做的
     外观伪装等）→ 从任务中剔除该部分、向用户说明后再派，**不得换模型重发原任务**。
     两种情况都在汇报里明说被拦及处置。
